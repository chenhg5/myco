# 工作流

工作流把一件常做的事写成固定的几步：每一步交给一个 agent、一台电脑，或者停下来等你决定，工作区按顺序往下走。比如「一个写、一个审，没过就改，最多三轮，最后你点头」；当你发现自己总在重复同一套交代时，就该把它做成工作流。

## 「工作流」页

点边栏顶上的 **工作流** 进来。有事等你决定时，边栏这一项右边会有一个橙色数字。

- **等你决定**：最上面，一件一张卡片，见下面「等你决定」。
- **我的工作流**：一行一个，写着几步、做什么，下面一行是最近一次运行：状态（等你决定、失败了、完成了、在跑）、这次做的是什么、多久以前。
- 每行右边有 **运行** 和 **⋯**（编辑、停用 / 启用、删除），右键也是同一个菜单。

工作流也跑在工作区上，你的电脑关着它也照样往下走；只是每一步的 agent 和电脑要在线，才能接手那一步。

## 新建一个

点右上角 **新建工作流**，有两种做法。

### 用现成的

挑一个，只要选谁来做、在哪台电脑：

- **写-审-改**：一个 agent 做，另一个审；没过就带着意见改，最多 3 轮；最后你点头。
- **改完跑测试**：agent 改，电脑上跑测试；没过就把报错交回去再改，最多 3 次。
- **分头做再汇总**：一个 agent 拆成两个方向，两个 agent 同时做，做完再合成一份。
- **发布前问你一句**：agent 列出要发的改动，你点「发布」后才在电脑上跑发布命令；一天没人点就不发。

选好以后，窗口下方马上画出流程图，确认没问题就点 **保存工作流**。

![用现成的「改完跑测试」：选谁来改、在哪台电脑跑测试，下面画出流程](shot:workflow-make)

### 让 agent 写一个

现成的不合适，就选 **让 agent 写一个**：

1. 选一个 agent。
2. 在「要怎么走」里用一句话说清楚：分几步、每步谁来做、什么时候要你点头。比如「每次有新需求，先让 Claude 写方案，Codex 审；审过了 Claude 实现，在 Studio Mac 上跑测试，过了再问我要不要合并」。
3. 点 **交给它写**。这会作为一条任务发给它，窗口跳到你和它的对话。它写好、检查好就存进来，出现在「工作流」页。

以后要加减步骤，也是让写它的 agent 去改。

## 打开一个工作流

点一行进到它的页面。标题下面写着在用 / 已停用、几步、第几版；右上角是 **编辑**、**运行** 和 **⋯**。下面四个标签：

- **运行记录**：每次运行一行（跑过以后默认打开这里）。上方的 **全部 / 在跑的 / 失败的 / 完成的** 用来筛选。
- **运行情况**：跑了几次、成功率、用时（中位数和慢的时候）、每次花多少钱，最近每次用时的柱状图，以及每一步的统计（次数、失败、重发和退回、用时、花费）。右上角可以只看某一版。
- **流程**：流程图（新建的默认打开这里）。卡片从上往下用箭头连着；往回走的线是虚线，写着最多几次；线上写着什么时候走这条（「通过」「没通过 · 最多 3 次」「选「就这样」」）；某一步左边的小红字说什么情况下整个运行算失败（「3 次还不行就失败」）。
- **输入和输出**：先是「运行时要填的」，然后每一步一块：左边「收到」什么，右边「交回」什么，每个字段写着名字、类型、是否必填和说明。

## 运行

1. 点 **运行**。
2. 窗口里按这个工作流的要求填好要的内容，比如「要改什么」，可选的项可以空着。
3. 点 **开始运行**，第一步马上交出去。

工作流发出的任务，在对应 agent 的对话里带着「工作流」标签，和平时的任务放在一起。

也可以让[自动化](#help/automations)到点或被 Webhook 调用时自动启动一个工作流。

## 一次运行的页面

在运行记录里点一次，进到它的页面。标题是这次要做的事，下面先是状态（在跑、等你决定、失败了、完成了），然后是哪个工作流、什么时候开始、用了多久、谁启动的、第几版。

- **数字**：总用时、其中干活多久和等人决定多久、走了几步、花了多少钱。
- **每一步**：一行一步，前面的圆标记表示状态：绿勾做完，红叉失败，橙点等你，绿点在做。写着谁做的、它交回的一句话或者为什么失败、用了多久。
  - **详情**：展开交给它的任务、它收到的输入、它交回的结果；结果符合约定时旁边有绿色的「符合约定」。
  - **日志**：它做的每一步（用了什么工具、怎么想的）。
  - **看对话**：跳到那条任务所在的对话。
  - 右上角能在 **列表** 和 **时间线** 之间切换。
- **流程图** 在下面，标着每一步的状态和跑了几次（×2）；点图里的一步，上面就只看这一步的每一次。
- **产物**：agent 交回的图片、文件，和最后交回的结果。
- **评分**：点 **打个分**，记下这次做得怎么样（质量、通过的测试、改动的行数……），写上越高越好还是越低越好。同名的分数会在「运行情况」里取平均，在对比里比高低。

右上角：还在跑的可以 **取消运行**；失败或取消了的，用 **从这一步重来** 从停下的那一步重新开始，前面做完的保留。**对比** 把这一次和另一次放在一起看：总用时、花费、每一步的用时和次数，以及打过的分，差多少一目了然；两次用的不是同一版时会提醒你。

## 等你决定

工作流里可以有「你来定」的一步：走到这里就停下，问你一句，比如「审过了，就这样吗？」。

这件事会出现在：

- 「工作流」页最上面的 **等你决定**，以及那次运行的页面里；
- 边栏「工作流」旁边的橙色数字；
- Mac 和 Windows 的 App 开着时，系统通知；手机 App 里也能决定。

卡片上写着哪个工作流、问的是什么、多久后过期。选一个选项（比如 **就这样** 或 **不要了**），想补充就在「想说一句就写在这里（可选）」里写一句，它就接着往下走。过期没选的，当作不做。

多久没人决定算过期，可以在编辑这一步时改（不限，或 30 分钟到 3 天）。谁来决定是写工作流时定好的，常见的是「启动它的人来决定」。

## 编辑

点 **编辑** 进到编辑页。左边是流程图，上面一排小标签「基本 / 1. 做 / 2. 审 / …」；点图里的一步或一个小标签，右边就改它。

- **基本**：一句话说明、「运行时要填的」、每个往回走的环最多走几次。
- **一步**：名字；**交给谁**（某个 agent、某台电脑，或「按分工挑空闲的…」再填一个分工，比如审查）；**超时**；**失败了再试** 几次；**要它做什么**；**交回什么**；可选的「收到的输入要符合」。
- 「要它做什么」里可以引用别的内容：`{{inputs.task}}` 是运行时填的，`{{steps.审.summary}}` 是前面一步交回的，工作区替换好再交出去。
- 「交回什么」一行一个字段：名字、类型（文本、数字、是 / 否、列表……）、是否必填、说明；**加一个字段** 再加一行。这就是这一步的约定，交回的结果不符合会被退回。表单写不了的规则，点 **用 JSON 改**。

改好点 **保存新版本**，存成新的一版；正在跑的还照旧用原来那版。没改就离开时不会问；改了没保存，会先问你「不保存就离开？」。名字和步骤的增减不在这里改，交给写它的 agent。

## 停用和删除

- **停用**：⋯ › 停用，它就不能再运行，历史都在；**启用** 恢复。
- **删除**：⋯ › 删除。运行记录一起删除，还在跑的会先停下；它发出去的任务和 agent 的回复都保留。

## 常见问题

**某一步一直不动？** 看那一步交给谁：agent 或电脑不在线时，任务会等着。点 **看对话** 能看到它的情况。

**结果被退回了？** 交回的内容不符合这一步「交回什么」的约定，失败原因里会写缺了什么（比如 approved is missing）。改一下这一步的要求，或者放宽约定。
