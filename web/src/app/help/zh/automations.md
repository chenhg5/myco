# 自动化

自动化让 agent 按时、按事件自己干活：每天早上汇总 issue、每周五写周报、CI 一失败就去看日志。它跑在工作区上，不靠你开着这台电脑，所以适合那些「到点就该做」或「出事就该有人看」的活。

## 「自动化」页

点边栏顶上的 **自动化** 进来。最上面三个数字：在运行几个、已暂停几个、最近一次是多久以前、结果如何。

下面「我的自动化」一行一个：

- 第一行是名字。
- 第二行是什么时候、发给谁：比如「工作日 09:00 发给 PM (Codex)」，或「Webhook 调用时 启动工作流 写-审-改」。
- 第三行是下次什么时候（「下次 明天 09:00」），暂停的写「已暂停」，只靠 Webhook 的写「等外部调用」；后面是上一次的结果：绿点已发送，灰点跳过，红点没发出去。

每行右边有 **运行**（马上发一次）和 **⋯**。右键一行也是同一个菜单：查看运行记录、编辑、立即运行、暂停 / 启用、删除。

页面最下面一直有「从模板开始」，随时能照着模板再建一个。

## 新建一个

点右上角 **新建自动化**，或者点下面的一张模板。模板有：每天早上汇总、每周五写周报、定时巡检、下班前写日报、CI 失败时排查。点模板会把名字、要做的事和时间都填好，你改改就能用；**从空白开始** 什么都不填。

编辑窗口从上往下，就是一个自动化干活的顺序：

1. **名字**：比如「每天早上汇总 issue」。
2. **做什么**：**给一个 agent 发任务**，或者 **启动一个工作流**（见下面「启动一个工作流」）。
3. **发给谁**：选一个 agent。它会在你和它的对话里收到这条任务。
4. **让它做什么**：像平时在对话里那样写一段话，越具体越好。比如「看一下昨天新开的 issue 和 PR，挑出要紧的，在这里回我一份清单」。
5. **什么时候**：两张卡片 **定时** 和 **Webhook**，可以选一个，也可以两个都选。
6. 点 **创建**。

还缺什么，按钮左边会写出来，比如「还没写让它做什么」。

![新建自动化：名字、做什么、发给谁、什么时候](shot:automation-editor)

### 定时

选了 **定时**，下面会出现频率：

- **每天**、**工作日**：再选几点几分。
- **每周**：点选星期几（可以多选），再选时间。
- **每隔几小时**：选隔 1、2、3、4、6、8 或 12 小时，再选在整点后第几分钟。
- **自定义**：写一条 cron 表达式（5 段）。

最后一行用大白话写出你选的，比如「工作日 09:00 · 下次 明天 09:00」，还有用的是哪个时区：新建时用这台电脑的时区。

### Webhook

选了 **Webhook**，外部系统（CI、监控、表单……）调用一个地址，就触发一次。外部带来的内容会放进你写的话里：

- 在「让它做什么」里写 `{{payload}}`，那里就会换成调用带来的整段内容；没写的话接在最后。
- 点说明里的 `{{payload}}` 小块，会把它插到末尾。

保存后会弹出 **Webhook 地址和密钥**：地址、密钥，和一条可以直接试的 `curl` 命令（「试一下」）。**密钥只显示这一次**，请马上复制保存。外部系统要用 POST 调用这个地址，并在请求头里带上 `Authorization: Bearer <密钥>`。

密钥丢了或泄露了：打开 **编辑**，点左下的 **重新生成密钥**，拿新的去换。

外部系统要能访问到你的工作区。工作区只在这台电脑和局域网里时，GitHub 这样的服务是调不进来的，先看[开放到公网](#help/public)。

### 上一次还没做完

「上一次的任务还没做完，就跳过这次」默认勾着：agent 手上的上一条还没做完时，这一次就跳过，免得活越堆越多。取消勾选就是每次都照样发。

自动化的内容存在工作区上，不是端到端加密的。

## 看运行记录

点一个自动化，进到它的页面。顶上是名字和状态（在运行 / 已暂停 · 什么时候 · 下次），右上角三个按钮：**编辑**、**立即运行**、**⋯**（暂停 / 启用、删除）。

**设置** 一栏列着：发给谁、什么时候（下面小字写着时区）、Webhook 地址（可以复制）、上一次没做完时跳过还是照发、让它做什么。

**运行记录** 一次一行：

- 左边是结果：已发送、跳过了（会写为什么，比如上一次的任务还没做完）、没发出去。
- 中间的小标签说是怎么触发的：到点、Webhook、手动。
- 时间：今天 09:00、昨天 18:30，下面写着多久以前。
- **看对话**：打开这次发出去的任务所在的对话，直接定位到那条。
- **调用内容**（只有 Webhook 触发的有）：展开这次调用带来的东西：内容类型、大小、是不是 JSON、记下的请求头，以及请求正文（JSON 会自动排好格式，可以复制）。只记下说明来源的请求头，不记密钥、签名、Cookie 和对方的地址。

有跳过或没发出去的时候，上方会出现 **全部 / 已发送 / 跳过 / 没发出去** 几个小按钮，用来筛选。最多保留最近 200 次。

![运行记录：展开一次 Webhook 调用，看它带来了什么](shot:automation-call)

自动化发出的消息，在对话里时间旁边有一个小小的「自动」标签，你一眼就知道这条不是自己手发的。agent 的回复照常出现在你和它的对话里。

## 启动一个工作流

自动化不光能给一个 agent 发任务，还能到点或被调用时启动一个[工作流](#help/workflows)：

1. 在 **做什么** 里选 **启动一个工作流**。
2. **哪个工作流**：选一个。
3. 下面会按这个工作流的要求，一行一个输入框（比如「要改什么」「测试命令」），填上这次要给它的内容。
4. 用 Webhook 触发时，可以把调用带来的内容填进去：整段用 `{{payload}}`，JSON 里的某个字段用 `{{payload.字段}}`，比如 `{{payload.issue.title}}`。

这种自动化的运行记录里，每次有一个 **看运行**，直接打开那一次工作流运行。这时「上一次」指的是上一次工作流运行还没结束。

![启动一个工作流：把 Webhook 带来的字段填进工作流的输入](shot:automation-editor-workflow)

## 暂停和删除

- **暂停**：⋯ › 暂停。它不再到点发送，Webhook 调用也不会触发；**启用** 恢复。
- **删除**：⋯ › 删除，确认后删掉。它不会再发消息，Webhook 地址也失效。已经发出去的消息和 agent 的回复都保留。

## 常见问题

**到点了 agent 没动？** 先看运行记录：已发送说明消息到了，agent 可能不在线，消息会等它上线再处理；跳过说明上一次还没做完；没发出去会写原因。

**电脑关着也会跑吗？** 会发。自动化在工作区上计时，到点就把任务发出去。但干活的 agent 所在的电脑要开着，它才能接手。

**提示这个工作区还不能用自动化？** 工作区的 myco 太旧，按页面上的提示升级工作区。
