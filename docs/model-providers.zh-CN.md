# 模型供应商

[English](model-providers.md) · **中文** · [README](../README.zh-CN.md) · [安装指南](../INSTALL.zh-CN.md)

模型供应商就是你自己的、存在工作区里的一份模型厂商 API key。存一次，以后在哪台电脑上开 Claude Code 或 Codex 的 agent 时都可以选它，而不必依赖那台电脑上碰巧有的登录方式。

可以选 MiniMax、DeepSeek、Kimi、OpenCode Go、智谱、通义、豆包、OpenRouter，或者 **自定义**：任何 Anthropic 或 OpenAI 兼容的地址。一个供应商可以带一个给 Claude Code 用的地址和一个给 Codex 用的地址，至少要有一个。

供应商是你自己的，不属于工作区。每个成员各自添加，别人看不到、也用不了你的。

## 在 App 里添加

1. 打开 **设置 › 模型供应商**。
2. 还没有时点 **新增模型供应商**；以后点 **新增**。
3. 选一家。内置的厂商会自动填好两个地址；选 **自定义**（"Anthropic 或 OpenAI 兼容的地址"）则自己填。
4. 填 **名字** 和 **密钥**（这家给你的 key）。展开 **地址和小模型** 可以改 **Anthropic 地址（Claude Code 用）**、**OpenAI 地址（Codex 用）** 和 **小模型（可不填）**。没有特殊说明就别改地址。小模型给 Claude Code 的后台小任务用，不填就用这家默认的。
5. **测试** 会用这个 key 读一次这家的模型列表，比如显示「读到 3 个模型：……」。**保存** 存下这个供应商。

也可以不离开新增 agent 的表单，就地添加：见下面的 **新开 agent**。

这一节会说明 key 是怎么存的。key 由谁保管，看工作区开没开端到端加密，这由你决定；两种情况下供应商都能用（见 **key 由谁保管**）：

> 开了加密：key 在这台电脑上加密后存到工作区，只有你自己的设备能解开，工作区看不到。新增 agent 时只写到那台电脑上（它的 env 文件，权限 600）。

> 没开加密：key 保存在 Hub 上，Hub 管理员能看到；团队共用建议开启端到端加密。点 **开启端到端加密** 会跳到 设置 › 工作区。

## 给 agent 用

**新开 agent**：在新增 agent 的表单里，先选 **用哪个 AI**，紧接着是 **模型从哪来**。第一项「『电脑名』上的登录或设置」表示不改那台电脑原来的配置；下面是你给这个 CLI 配了地址的供应商。**+ 用自己的 API key** 可以就地新增：选一家（或 **自定义地址**），填 key，点 **测试**，再点 **保存并选用**，它会存进 设置 › 模型供应商 并直接选上。选了供应商，**模型** 会列出从这家读到的模型（不选就是 **它默认的模型**），下面一行写着 key 由谁保管。

**已经在另一台电脑上的 agent**：打开这个 agent，点 **服务商** 一行。选标着 **我的模型供应商** 的那个供应商，再选 **模型**（不选就是 **它默认的**）。**跟随它那台电脑** 改回那台电脑自己的设置。只影响这一个 agent。如果是这台电脑上的 agent，**服务商** 一行改的是这台电脑自己的服务商设置。

可选的模型来自这个供应商上一次 **测试** 的结果。还没读到过就留空，用 CLI 自己的默认模型；在 **设置 › 模型供应商** 里点 **测试** 可以读出列表。

## 换了 key

在供应商那一行点 **编辑**，在 **密钥** 里填新 key，**保存**。「填了就换成新的 key，用它的 agent 会提示推送。」

还有 agent 用着旧 key 时，供应商那一行会出现 **推送新 key（N）**；agent 的 **服务商** 一行也会写「『名字』的 key 已更新，它还在用旧的 · **推送**」。推送完会显示「新 key 已发给 N 个 agent，它们从下一条消息开始用。」没发成的 agent 会列出名字和错误。

## key 由谁保管

**开了端到端加密：**

- key 先在你这台电脑上加密，才存到工作区。只有你自己的设备能解开；Hub 读不到，也不会写进日志。工作区另外保存名字和地址，用来显示。
- 给 agent 用时，key 只到运行它的那台电脑：在你的电脑上解开，再为那台电脑加密，写进 agent 的 env 文件（`~/.myco/env/<agent>.env`，权限 600）。agent 用的就是这份。
- 后来新加的设备自己解不开 key。在你另一台已经能解开它的设备上打开一次 App，它会为这台新设备再加密一份；在那之前，供应商那一行会显示 **这台设备还解不开 key**。如果已经没有能解开的设备，用 **编辑** 重新填一次 key。
**没开端到端加密**（自己一个人用、Hub 也是自己的，没有问题；团队共用建议打开）：

- key 由 Hub 用工作区自己的密钥加密后保存：工作区数据库旁边的 `provider-secret.key`，权限 600。Hub 管理员能看到。供应商那一行会标 **Hub 保管**，key 只显示末四位（`key ···abcd`）；短于 12 个字符的 key 只显示已保存，不露任何一部分。
- Hub 只把 key 发到运行这个 agent 的那台电脑，走 HTTPS；它不会出现在 agent 的设置、消息或日志里。你给它选定的那个 agent，由它的 runner 来取 key；在某台电脑上新开 agent 时，这一次启动会单独拿到一份一次性授权，只能用在这一次，十分钟内有效。每个调用者每分钟最多取 6 次，超过会提示稍后再试。每发一次都会记一条审计，里面没有 key。
- 如果那个密钥文件丢了（比如换服务器没带上），供应商会显示 **key 已丢失**：用 **编辑** 重新填一次 key，或者从备份恢复 Hub。

**之后打开或关掉加密**：打开后，App 下次列出供应商时，会把 key 改成只有你的设备能解开，Hub 删掉自己那份。关掉后，供应商会提示工作区已关了加密，并给出 **交给 Hub 保管**，点之前会先问你。已经配好的 agent 两种情况下都照常用各自电脑上那份。

- 备份要当机密文件保管。Hub 的备份里同时有 `provider-secret.key` 和数据库；运行 agent 的电脑上，它的 env 文件里是能直接用的 key，那台电脑的备份也就带着它。
- 你的供应商只属于你：工作区里的其他人看不到、也用不了。

## 常见问题

### 「测试」失败，提示怎么看？

提示里只会写那家的主机和 HTTP 状态码，比如 `models from api.deepseek.com: HTTP 401`，不会带出 key。401 或 403 通常是 key 被拒；404 通常是地址不对；5xx、`unreachable`、`cut off` 或超时，是厂商那边或网络的问题。先核对 key 和地址，再看这台电脑能不能连上厂商。

### 换了电脑或新加设备怎么办？

在你另一台已经能解开 key 的设备上打开一次 App，它会为这台新设备再加密一份；能解开以后，供应商那一行就不再显示 **这台设备还解不开 key**。如果已经没有这样的设备，用 **编辑** 重新填一次 key，再 **保存**。

### 删掉供应商以后，已有的 agent 会怎样？

删除时的确认框写着：「N 个 agent 在用它。它们会照常用各自电脑上已经写好的那份，App 上会提示改选或者清掉。」这些 agent 会继续用各自电脑上那份，它的 **服务商** 一行会显示「它用的模型供应商已删除：它那台电脑上的那份照常能用；改选一个，或者改回跟随它那台电脑。」新开的 agent 不会再列出这个供应商。在 App 里删除不会去动那些电脑；需要的话，给它改选一个供应商，或者改回跟随它那台电脑。


### MiniMax 地区与连接测试

在供应商编辑框或新增 agent 的表单中选择 **MiniMax 地区**：**国际**使用
`api.minimax.io`，**国内**使用 `api.minimaxi.com`。key 在哪个站创建，就选哪个
地区；另一站可能返回 HTTP 401。切换地区会明确更新 Anthropic 和 OpenAI 两个地址；
测试不会自动把 key 发到另一站。既有供应商保留原地址和 `minimax` 标识，401 提示会
说明 key 或地区可能不匹配。编辑时若不重新填 key，请先保存地区或地址修改再测试；
测试使用的是已保存、与 key 一起封存的地址。

正常测试读取账号的模型列表。如果已知 MiniMax 接口不提供列表，用户主动验证
（点击 **测试**，或在新增 agent 表单中点击 **保存并使用**）
时可以在所选接口上发起一次小对话（最多 16 个输出 token），可能消耗少量额度。
只有有效的 API 响应才算通过；HTTP 200 中的 API 错误不算。此时界面明确显示
**预设模型**，不冒充从账号读取的列表。后台模型发现不会生成对话；限流、服务端
故障或网络错误不会触发该回退。

MiniMax 官方的 [Anthropic](https://platform.minimax.io/docs/api-reference/text-anthropic-api)
和 [OpenAI](https://platform.minimax.io/docs/api-reference/text-openai-api)
文档当前列出 `MiniMax-M3` 和 `MiniMax-M3.1-Flash`；真实模型列表优先于这些预设。
