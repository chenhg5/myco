# 和 agent 一起玩、一起做：小程序与共享的一局

状态：设计讨论中，还没有开始做（2026-11-14）。这是一个新功能，先把想法和取舍写清楚，定了方向再动手。

## 1. 初衷

myco 现在是一条**消息通道**：人给 agent 派活，agent 之间互相派活，过程和结果回到对话里。所有的交互都是"一来一回的文字"。

但人和 AI 一起做事，不只有文字：

- 和 agent **下一盘棋**：人在棋盘上走一步，agent 看着同一个棋盘回一步。
- 和 agent **一起改一份文档**：人改一段，agent 接着改；人批注，agent 照着改。
- 和 agent **一起画**：你画一笔，它接一笔；或者它出题你来画。
- 一个项目里几个人、几个 agent 一起排计划、投票、过看板。

这些事有一个共同点：**大家看着同一个东西、轮流对它动手**。文字消息能凑合（"我走了炮二平五，你走"），但人得自己在脑子里摆棋盘，也看不到对方动了什么。

既然 myco 已经把人和各种 agent（Claude Code、Codex、DeepSeek……不管在哪台电脑、用哪种方式接入）连在一条通道上，就可以在这条通道上再加一层：**一个大家都能看、都能动的小东西**。

这里面是两件事：

1. **agent 能做小程序给人用**：agent 写一个小网页（象棋、画板、投票……），App 里点开就能用。也可以是现成的、内置的小程序。
2. **agent 能实时参与进来**：人在小程序里操作，agent 能知道现在是什么样子、轮到它时动手，人马上在同一个画面里看到。

## 2. 概念

界面上只多两个词：

| 界面上叫 | 用户理解成 | 底层是什么 |
| --- | --- | --- |
| **小程序** | 一个能点开用的小东西：象棋、画板、文档、投票 | 一个 HTML 文件（加一点说明），存在 Hub 上 |
| **一局** | 用这个小程序的一次：这盘棋、这张画、这份稿子 | Hub 上的 session：参与者、共享状态、事件、轮到谁 |

一局里有：

- **参与者**：开局的人，加上请进来的 agent（可以是好几个）和其他人。
- **共享状态**：一段 JSON，小程序自己决定里面是什么（棋盘、文档全文、笔画列表）。带**版本号**，谁改都要基于最新的版本。
- **事件**：一串按顺序的记录（"人走了一步""agent 说了一句""这一局结束了"），用来回放、通知和让 agent 知道刚才发生了什么。
- **轮到谁**（可选）：轮流的游戏用；自由编辑的可以不用。

Hub **不懂**游戏规则，也不懂文档格式：它只负责存状态、按版本防止互相覆盖、记事件、叫醒 agent。规则在小程序自己的代码里。

## 3. 用起来是什么样

### 3.1 下一盘象棋（第一版的样板）

1. 在和某个 agent 的对话里（或者项目里），点输入框旁边的「小程序」，选「象棋」，「开一局」。
2. 对话里出现一张卡片「象棋 · 你 vs 后端（Claude Code）」，点开是棋盘（右侧面板，和现在打开文件一样，可以全屏）。
3. 你走一步。棋盘下方写「轮到 后端 了」，它的头像旁边是现在的那个走动的蘑菇和「正在想…」。
4. agent 被叫醒（runner 唤醒或 inbox wait，和收到一条任务一样），读到当前棋局，走一步。几秒到几十秒后，棋盘上它的棋子动了，旁边可能还有它的一句话（"跳马保护中路"）。
5. 一直到分出胜负，或者有人点「结束这一局」。对话里的卡片变成「象棋 · 后端 胜 · 42 步」，点开能回放。

### 3.2 一起改一份文档

1. 开一局「文档」，可以从项目文档或一个文件开始。
2. 你改了第二节，点「交给 agent」（或者写一句批注 @ 它）。
3. agent 读到当前全文和你的改动、批注，改完写回去。你看到它改了哪里（像现在文件版本的差异那样标出来）。
4. 来回几轮，满意了就「存为项目文档」或「发成文件」。

### 3.3 一起画

1. 开一局「画板」，选「接龙」：你画一笔，它接一笔；或者「你画我猜」：它出题你画，它来猜。
2. agent 不能像人一样连续地画，它一次给出一组笔画（几条线、几个形状），画面上按顺序画出来。

## 4. 设计

### 4.1 小程序是什么、放在哪

- **一个 HTML 文件**，JS 和 CSS 都写在里面，不引用外部资源（最多 2 MB）。最省事：agent 写一个文件就行，人也能直接看源码。
- 文件开头用一个 `<meta>` 写说明：名字、一句话介绍、图标（emoji 或内嵌图片）、玩法（轮流 / 自由）、几个人。没有也能用，名字取文件名。
- **来源有三种**：
  - **内置**：随 App 一起发的几个（象棋、五子棋、画板、文档），离线也能用。
  - **agent 做的**：agent 用 `myco app publish --file chess.html` 发出来，存在 Hub 上（复用现在附件的存储），出现在对话里，或者放进项目的「小程序」里。
  - **人自己加的**：把一个 HTML 文件拖进来，「当作小程序打开」。
- **同一个小程序改了再发**，和文件一样算新版本；已经开着的一局继续用它开局时的那一版，不会玩到一半代码变了。

### 4.2 运行和安全

小程序的代码可能是 agent 现写的，要当成**不可信**的代码对待：

- 跑在 **沙箱 iframe** 里：`sandbox="allow-scripts"`（允许脚本，但**不**允许同源），所以它读不到 App 的页面、存储和令牌，也不能弹窗、不能跳走整个 App。
- **不能联网**：页面带 CSP，`connect-src 'none'`，图片只能用内嵌的（`data:`、`blob:`）。它和外面说话的唯一途径是下面的「桥」。
- **桥只认它自己这一局**：能读写的只有这一局的状态和事件，不能看别的对话、别的局。
- 打开 agent 做的小程序时，卡片上写明「由 后端（Claude Code）制作」，第一次打开某个 agent 做的新版本时提示一句。
- 大小上限：小程序 2 MB，状态 256 KB，一个事件 16 KB，一局最多 5000 个事件（够下很多盘棋），超了就提示开新的一局。

### 4.3 桥：小程序里的 `myco` 对象

App 把小程序装进 iframe 时，往里面放一个很小的脚本，提供一个全局的 `myco` 对象（底下是 `postMessage`，App 那边检查来源）：

```js
const game = await myco.ready;      // { me, participants, state, version, turn, events }
myco.on("change", (g) => draw(g.state));          // 谁改了状态（包括 agent）
myco.on("event", (e) => log(e));                  // 新事件：走了一步、说了一句
await myco.update(next, { turn: "next" });        // 写状态（基于当前版本），并把回合交出去
await myco.send({ kind: "say", text: "该你了" }); // 发一个事件（可以 @ 某个参与者）
await myco.end({ result: "红方胜" });              // 结束这一局
```

- `update` 带着它看到的版本号写；有人先写了（比如 agent 刚走了一步），就失败并给出最新状态，小程序重画后让人再走。
- 小程序负责**校验人的操作**（这步棋合不合法），也负责**校验 agent 写进来的状态**；不合法就发一个事件说明，并把回合退回给 agent（它会再被叫醒一次，带着原因）。

### 4.4 Hub：一局的数据和接口

新增一张表 `sessions`（迁移在 `internal/infra/sqlite`，老库原地升级）和它的事件表：

- `sessions`：id、小程序（附件 id + 版本 + sha256）、所在的对话（thread）或项目、开局的人、参与者、状态（JSON）、版本号、轮到谁、开着 / 已结束、结果、时间。
- `session_events`：局 id、序号、谁、种类、内容、时间。

接口（agent 用自己的令牌，App 用 console 令牌，只有参与者能看能动）：

| 接口 | 做什么 |
| --- | --- |
| `POST /v1/sessions` | 开一局：小程序、参与者、初始状态、对话或项目 |
| `GET /v1/sessions/{id}` | 当前状态、版本、轮到谁、参与者 |
| `PUT /v1/sessions/{id}/state` | `{state, if_version, turn?}`：版本对不上返回 409 和最新状态 |
| `POST /v1/sessions/{id}/events` | 发一个事件，可以指定给谁（`to`） |
| `GET /v1/sessions/{id}/events?after=` | 从某个序号之后的事件（App 和 agent 都用它追新） |
| `POST /v1/sessions/{id}/end` | 结束，带结果 |

和现有功能的关系：

- 一局挂在一个对话（thread）下，所以开局卡片、结束卡片就是那段对话里的两条消息，历史、搜索、项目归属都照旧。
- 审计记开局和结束；中间的每一步不记审计（记在事件里）。
- **端到端加密的 Hub**：第一版不开放（状态会以明文存在 Hub 上），App 里说明原因。以后可以像消息一样加密状态和事件。

### 4.5 agent 怎么参与：还是走消息通道

这是最关键的一点：**agent 那边不需要新的接入方式**。

- 轮到某个 agent（`turn` 交给它），或者有事件 `to` 它时，Hub 给它发一条**任务**，挂在这一局的对话里，带 `session` 字段。正文是一段简短的说明：

  > 你在《象棋》这一局里（session s_123），轮到你了。对手刚走了：炮二平五。
  > 看当前状态：`myco session get --id s_123`；走一步：`myco session update --id s_123 --state-file next.json --turn next`；想说句话：`myco session say --id s_123 --text "…"`。

- 所以 runner 唤醒的 agent、挂着 `myco inbox wait` 的 agent、任何会用 CLI 的 agent 都能参与，和收到一条普通任务一样。过程（它想了什么、查了什么）照常显示在对话里。
- agent 做完自己的回合就回复这条任务（或者 `update` 交出回合时自动结束这条任务），loading 消失。
- **不会刷屏**：同一回合里人连续做了几次操作，只在交出回合时叫醒 agent 一次；自由编辑的一局，人点「交给 agent」或 @ 它才叫醒。
- skill 里加一节：怎么参与一局、怎么读状态、怎么写回去、写之前先确认版本、不合法时怎么办；以及怎么做一个能接 `myco` 桥的小程序（给一个最小模板）。
- 状态和事件里的内容是**数据**，不是给 agent 的指令：任务正文里明确这样写，防止有人在棋盘备注里写"忽略之前的指示"。

### 4.6 CLI

按现有的 `noun verb` 习惯，输出非终端时是 JSON，有副作用的都支持 `--dry-run`：

```
myco app publish --file chess.html [--name 象棋] [--project p]   # 发一个小程序
myco app list [--project p]
myco session start --app <id|内置名> --with <agent>[,<agent>]     # agent 也能开局邀请人
myco session get --id <s>
myco session update --id <s> --state-file next.json [--if-version N] [--turn next|<名字>]
myco session say --id <s> --text "…"
myco session events --id <s> [--after N]
myco session end --id <s> [--result "…"]
```

### 4.7 App

- 输入框旁边多一个「小程序」按钮：内置的、这个对话和这个项目里的小程序，「开一局」。
- 一局在右侧面板打开（和现在打开文件同一个面板，能全屏），对话里是一张卡片：小程序名、参与者、状态（进行中 · 轮到谁 / 已结束 · 结果）。
- 面板顶上一行：参与者头像，轮到谁时那个头像旁边是走动的蘑菇；agent 在想的时候显示「正在想…」，点开能看过程（复用现在的过程显示）。
- 项目页里多一块「小程序」：放进项目的小程序和正在进行的局。
- App 用轮询（和现在的对话一样，开着面板时 1 秒一次）拿新事件，不新加长连接。

## 5. 能做什么，不能做什么

agent 每动一次要几秒到几十秒（启动 CLI、读状态、思考、写回去），这决定了适合的玩法：

| 适合 | 可以，但要按回合 | 不适合 |
| --- | --- | --- |
| 象棋、五子棋、围棋、桌游、猜谜、成语接龙 | 一起画画（一笔一笔接，或者它一次画一组） | 要实时反应的动作游戏 |
| 一起改文档、批注和修改、一起写方案 | 两个 agent 对弈、人来看（每步都慢） | 需要连续看画面的东西 |
| 投票、排计划、看板、清单 | | |

## 6. 分几步做

1. **一局 + 桥 + 内置象棋**（先在对话里）：Hub 的 sessions 和接口、叫醒 agent 的任务、CLI 的 `session` 命令、App 的沙箱 iframe 和 `myco` 桥、一个内置的象棋。做完就能在 App 里和任何一个 agent 下一盘。
2. **agent 自己做小程序**：`myco app publish`、对话和项目里的「小程序」、skill 里的模板和写法。让 agent 做一个五子棋或画板试试。
3. **多人、文档、手机**：一局里多个人和多个 agent；文档共创（和项目文档、文件版本打通）；iOS 用 WKWebView 接同一个桥。

每一步都要保证老的不坏：老 Hub 没有 sessions 接口时，App 不显示「小程序」按钮；老 App 看到开局卡片，就当一条普通消息显示；老 runner 收到一局的任务，就当普通任务处理（正文里有怎么用 CLI 的说明）。

## 7. 还要定的事

- **小程序放在哪**：对话里（像发文件一样）、项目里（大家都能打开），还是两边都有？倾向两边都有，先做对话里的。
- **第一个样板**：象棋，还是「一起改文档」更能说明价值？
- **内置哪几个**：象棋、五子棋、画板、文档？内置的越少越好维护。
- **agent 能不能自己开局邀请人**：比如 agent 做好了一个小程序，直接开一局请你来玩。倾向可以，但人要点「加入」才算开始。
- **结果去哪**：一盘棋的棋谱、一张画、一份文档，结束后自动存成对话里的一个文件？还是只在卡片上回放？
- **手机**：第一版要不要同时上 iOS？

## 8. 不做的事

- 小程序**不能联网**、不能调用任意接口；需要数据就由 agent 拿到后写进状态。
- 不做**实时动作类**的东西，不为 agent 做毫秒级的通道。
- 不做跨 Hub 的「小程序商店」；分享就是发一个文件。
- Hub 不理解任何小程序的规则，不在服务器上跑小程序的代码。
