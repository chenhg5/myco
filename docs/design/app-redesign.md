# myco App 第三版：从"节点网络"改成"项目和同事"

状态：已实现（2026-11-12 合入 main），还没有发版。界面规范在 [app-ui.md](app-ui.md)（第 0 节"概念"和第 6.12–6.14 节），改界面时以它为准。本文记录这一版**为什么改、按什么思路改**，以及改的过程中定下的取舍。它取代了第二版的导航（"对话、节点、机器"三张表）和"节点、机器"的叫法；第二版的上手流程（App 内置 CLI、本机 Hub 一键启动、连接链接）照旧。

## 1. 初衷

v2 之后 App 已经能用：能加节点、能派任务、能看对话。但给不熟悉 myco 的人用时，问题出在**概念**上，不在功能上：

- 界面上满是工程词：Hub、节点、机器、runner、shell 节点、exec、allow_from。用户得先懂 myco 的架构，才知道该点哪里。
- myco 有点像 Tailscale（把散在各处的电脑连成一张网），又和具体的 agent 绑在一起。按"网络"来组织界面（Hub → 机器 → 节点），对用户就成了**管理一张网**；而用户想做的是**让几个 AI 一起把一件事做完**。
- 用户记不住哪个节点是哪个会话：名字是 `glenn-mac-claude-x9k2` 这种，头像是一样的图标。
- 侧栏是"对话、节点、机器"，各自一张大表。想知道"这件事进展到哪了"，要在几张表之间来回找。

Glenn 给这一版定的方向是：**把用户当成不懂技术的小学生**，一切做得丝滑、简单，界面上只出现用户自己的概念，不要技术概念；不背历史包袱，按新思路重做一版。

## 2. 新的概念：四个词

界面上只用这四个词，每个都是用户本来就懂的东西。底层的叫法只在 CLI 和成员卡片的「详细信息」里出现。

| 界面上叫 | 用户理解成 | 底层是什么 |
| --- | --- | --- |
| **工作区** | 一个团队（或自己）的地盘 | Hub |
| **项目** | 一件要做成的事，和一起做这件事的成员 | project |
| **agent**（成员） | 一个有名字、有头像、有分工的 AI 同事 | AI 会话节点 |
| **电脑** | 交给 agent 用的一台电脑上的一个文件夹；打开就是终端 | shell / exec 节点 |

几个命名上的取舍：

- **Hub 叫"工作区"**。考虑过"服务器"，但用户并不关心它在哪台服务器上，只关心"这是哪个团队的"。工作区还可以切换，这也是用户熟悉的做法（Slack、Notion）。
- **shell 叫"电脑"**。一开始叫"工作空间"，和"工作区"太像，改成了"电脑"：agent 在一台电脑的某个文件夹里跑命令，用户一听就懂。
- **"机器"不单独出现**。一台电脑上可以有好几个文件夹，用户看到的是"Studio Mac · ~/code/myco"这样一个整体，不是"机器 → 文件夹 → 终端"三层。机器只在电脑页底部的"已连上"一行里露面，用来连接和移除。
- **"节点"彻底不说**。agent 就是成员，电脑就是电脑。

## 3. 用户动线

改版前先想清楚了"理想的用户怎么用、为什么愿意持续用"，再按这条动线排界面：

1. **先有一个项目**。第一次打开就是"先建一个项目吧"，只要一个名字。哪怕是空项目也行：项目是用户脑子里的那件事，有了它，后面的一切才有地方放。
2. **一句话加 agent**。把一句话发给任何 AI 会话（Claude Code、Codex、claude.ai……），它自己装好 myco、写上自己的分工、加入这个项目；弹窗开着时，新来的 agent 当场出现（"✓ 后端工程师 加入了"）。
3. **需要时给它们一台电脑**。选哪台电脑、哪个文件夹，项目里的 agent 就都能在里面跑命令。加 agent 和加电脑没有先后。
4. **在群里派活**。项目就是一个群：看大家在干什么，在底部选一个成员派活。
5. **想细聊就单聊**。点成员进一对一的对话，看它的每一步、纠正它。
6. **成员可以去别的项目**。同一个 agent 可以在好几个项目里，像同事参加好几个项目组。

让人"持续用"的，是第 4、5 步：打开 App 就知道每件事进展到哪、谁在干活、谁卡住了，派活像发消息一样顺手。

## 4. 关键设计和理由

### 4.1 以项目为中心的侧栏

侧栏从上到下：**项目**、**还没进项目的**、**电脑**、**成员**；最底下是工作区切换器。

- 项目只写名字。曾经给每个项目配首字色块，但它不带任何信息，去掉了；有成员在干活时，右边一个绿点。
- 电脑直接列在侧栏里，点一下就是终端，不用先进管理页。
- "成员"用几个叠在一起的小头像代替图标，看一眼就知道这里有人。
- 设置不占侧栏：一般只设一次，从工作区菜单（或 ⌘,）进。

### 4.2 群聊不是广播

项目的主视图是群聊，但**每条消息只有一个收件人**。原因：agent 收到消息就会动手，"发给所有人"等于让所有人同时干同一件事。所以输入框写明"发给 X"，默认是上次发给的人或项目的协调者；第一次发时提示"只有 X 会收到这条，其他成员看得到但不会动手"。群聊的价值在于**看得见**：大家的任务都在一个流里。

### 4.3 拟人化：名字和头像

- 每个 agent 是一个像素小蘑菇，帽子颜色、斑点、表情由它的 id 决定，永远一样；右下角小角标说明是 Claude（橙色星号）还是 Codex（蓝紫色 `>_`）。电脑是一个小终端屏幕。
- 名字优先用它的分工（"后端工程师"）；没有分工时用"文件夹 + 助手"，重名的加"二号""三号"，不再显示 `xxx-claude-x9k2`。
- 目的就一个：**让用户认得出谁是谁**，像认同事一样。

### 4.4 工作区完全隔开

最初保留了"全部工作区"视图，用起来很乱：项目、成员、电脑混在一起，每个弹窗都要问"放在哪个工作区"。改成一次只看一个工作区：切换后所有页面、弹窗、筛选都只在这个工作区里，不再出现选择工作区的下拉框，也不跨工作区操作。切换器放在侧栏最下面，因为它很少用。

### 4.5 添加 agent：四种方式，一句话就够

弹窗是四个标签：

1. **已有的**：这个工作区里还不在本项目的 agent（在别的项目，或还没进项目），点一下加进来。有这样的 agent 时默认打开这一页。
2. **这台电脑上的**：列出本机最近的 Claude Code / Codex 会话（可以搜），点一下复制一份会话加入。
3. **发一句话**：给其他电脑、云端或任何 AI。
4. **新开一个**：选电脑、选用哪个 AI、填文件夹。

"发一句话"原来是一大段 prompt（装 myco、`myco join --display-name …`、怎么收消息）。用户的反馈是"一句话变成一段话了"。解决办法是**把步骤收进链接**：链接可以带项目（`/j/<token>/<项目>`），它下载的脚本装完 myco 以后，最后打印 agent 该做的下一步。所以那句话只剩一条命令：

> 加入 myco：在终端运行 `curl -fsSL <链接>/<项目> | bash`，再照它最后的输出做完。

项目名放在路径里，不用 `?project=`，因为 zsh 会把没加引号的 `?` 当通配符。旧版工作区不认识这种链接，App 会给出完整的步骤。

### 4.6 加电脑不用等 agent

电脑必须写明"谁能在上面跑命令"；名单留空等于所有 agent 都能用，不安全。原来的做法是先要有 agent 才能加电脑，用户觉得这两件事不该有先后。现在空项目里也能先加电脑：它先锁给一个谁都不是的占位名字，第一个 agent 进项目后，App 自动把使用权换成项目里的 agent。

### 4.7 成员卡片：先回答"它是谁"

用户最常见的困扰是"忘了这是哪个会话"。成员卡片因此按这个顺序排：

1. 头像、名字、分工（只占一行，长了用省略号）、状态、单聊按钮；
2. **它是谁**：在哪（claude.ai 云端，或"这台电脑 · ~/code/myco"）、用的哪个 AI 和模型、来自哪个会话（在本机时显示会话的第一句话）、主人、什么时候加入；
3. **最近在做**：最近 7 天做完、在做、失败三个数，和最近三件事；
4. 所在项目；
5. 「详细信息」（默认折起）：技能、运行细节、标签、往来、修改记录、身份；
6. 管理：允许谁派任务、复制、踢下线、删除。

原来"更多信息"要再弹一个面板，现在合成一张卡。技能也放进了折叠区：用户基本不会自己编辑技能，它主要是给其他 agent 挑人用的。

### 4.8 安静的界面

- 设置页不用大块红色、绿色：状态写成"● 已连接"这样的文字；移除、停止平时是描边的中性按钮，指上去才变红；红色实心只留给确认弹窗里的最后一步。
- 弹窗里的选项按钮、文件夹快捷选项都做小；路径显示成 `~/…/父目录/文件夹`，悬停看全路径。
- 一个弹窗底部只有一排按钮。

### 4.9 输入框

群聊输入框学 Claude / Codex：上面是整宽的文字区，随内容变高，到大约 10 行才出现滚动条；下面一排小工具，左边是"发给 [成员 ▾]"，右边是发送。这一排工具也是以后放**附件和语音**的位置，加上去不用改布局。

## 5. 改版过程中的几条经验

- **先改叫法，再改界面**。概念定下来（工作区 / 项目 / agent / 电脑）以后，大部分界面问题自然就有了答案。命名先后改过两次（工作空间 → 电脑，Hub → 工作区），都是因为和别的词撞了。
- **每一步都在真机上看**。很多问题只在 Mac App（WebKit）里出现：输入框不会变高（WebKit 不支持 `field-sizing`）、成员卡片里的按钮和描述被压扁（滚动的 flex 容器会压缩子元素）。模拟环境的截图看不出来。
- **少一层就少一层**。"更多信息"的第二个面板、电脑的"机器 → 文件夹"层级、"全部工作区"，去掉以后都更好用。
- **缓存要跟上**。项目、对话、单聊的对方都先显示上次的内容，再在后台刷新。在每个请求人为加 0.6 秒延迟的测试里，切回项目约 0.1 秒有内容，第二次打开单聊约 0.1 秒。

## 6. 还没做 / 待定

- **附件和语音输入**：输入框已经留了位置，功能还没做。
- **你自己在 App 里用电脑终端**：从 App 发出的消息不在电脑的"谁能用"名单里，名单里也写不进 App 自己。真机上你从 App 往电脑终端发命令，很可能被拒绝；模拟环境里看不出来。需要 Hub 或 runner 给 App 自己放行。
- **"最近在做"是估算**：从工作区最近的对话列表里统计，对话很多时较早的会漏算。要准确需要 Hub 提供按 agent 的统计。
- **旧版工作区**：链接带项目、一条命令的"发一句话"，需要工作区的 myco 也更新到这一版；旧版仍显示完整步骤。
- **云端电脑的名字**：像 `51147689d11e` 这种由电脑自己报上来的名字，要不要隐藏或显示成"云端电脑"，还没定。
