# 用语音和 agent 们说话：语音助手的方案

状态：方案讨论中，还没有开始做（2026-11-14）。定了方向再动手。

## 1. 想解决什么

现在跟 agent 打交道全靠打字：派活、补充、看进展、回答它的问题。语音输入（v0.19.6）只是把说的话变成字填进输入框，本质还是打字。

想要的是**像打电话一样**：说一句，马上有回应；一边走一边说「让后端把登录那个 bug 修了，修完跑一遍测试」，它确认一下就去办；过一会儿它主动告诉你「后端修好了，测试都过了，要我让前端也看一眼吗」。

难点在于：真正干活的 agent（Claude Code、Codex……）一件事要几分钟到几十分钟，它们不适合直接对着人说话。所以需要一个**专门负责说话的「语音助手」**，它反应快、会聊天，自己不写代码，负责听懂你、替你派活、盯进展、用几句话告诉你结果。

## 2. 主流是怎么做的

（据我了解，截至 2026 年年中；具体产品细节可能有变化。）

- **两种技术路线**：
  - **级联式**：语音识别（ASR）→ 文本大模型 → 语音合成（TTS），三段都用流式。LiveKit Agents、Pipecat 这类开源框架都是这个结构，再加上语音活动检测（VAD）判断你说完没有、打断处理。好处是每段都能换，模型选择多，文字天然留档，便宜；难点是延迟要靠三段都流式才能压下来。
  - **端到端语音模型**：OpenAI 的 Realtime 接口、Gemini Live、ChatGPT 的高级语音，直接听声音、出声音，延迟低、语气自然，但贵，能选的模型少，中间的文字要另外转出来。
- **「说话的」和「干活的」分开**：OpenAI 的语音 agent 示例里有一种「前台 + 主管」的做法，前台用快模型陪你聊天，遇到要动脑或要调工具的事就交给后面更强、更慢的模型或 agent，结果回来再由前台说给你听。ChatGPT 语音里让它「去查一下」、做长任务，也是这个思路：说话的一直在线，慢的事在后台。
- **体验上的几个共识**：
  - 端到端的回应要在 **1 秒左右**开始，否则就像对讲机；
  - **能打断**：它在说话时你一开口，它就停下来听；
  - **判断说完了没**：不能你一停顿它就抢话，常见做法是 VAD 加「这句话语义上说完了没」的判断；
  - **说得短**：语音里不念长段落、代码和链接，细节放在屏幕上。

你倾向的「语音转文字 + 文本大模型 + 文字转语音」就是级联式，我也建议先这样做：myco 本来就是文字的世界，文字留档、能换模型、成本低，延迟可以靠流式和短回答压住。以后想要更自然，可以把中间换成端到端模型，外面的设计不用动。

## 3. 设计

### 3.1 三个角色

| 角色 | 是谁 | 做什么 |
| --- | --- | --- |
| **你** | 说话的人 | 用语音（也可以随时打字）交代事情、提问、拍板 |
| **语音助手** | 一个新的、轻量的 agent，跑在 App 里 | 听你说、和你聊、把你的意思写成清楚的任务派给对应的 agent，盯它们的进展和提问，用几句话说给你听 |
| **干活的 agent** | 现在的 Claude Code、Codex、shell 节点…… | 照常收任务、干活、报进展、回复，**完全不用改** |

语音助手**不写代码、不碰电脑**。它能做的事就是 myco 已有的那些动作，用工具调用的方式交给它：

- 派活：`send`（给谁、内容、哪个项目）；
- 补充：`steer`（给正在做的任务加一句）；
- 回答 agent 的提问：`answer`（`message ask` 的那张卡片）；
- 停下：`stop`；
- 查：谁在线、某个任务做到哪了（进展、计划、最后几步）、某个项目里有谁。

### 3.2 一轮对话怎么走

```
你说话 ─▶ 语音识别（流式，边说边出字）
            │  VAD + 「说完了没」判断
            ▼
        语音助手（文本大模型，流式输出 + 工具调用）
            │                         │
            │ 要回你的话               │ 要办的事
            ▼                         ▼
        语音合成（按句子流式）      myco：派活 / 补充 / 回答 / 停
            │                         │
            ▼                         ▼
        扬声器                     干活的 agent（几分钟）
                                      │ 进展、提问、回复
                                      ▼
                         语音助手：值得说的，挑空档说给你听
```

- **延迟目标**：你说完到它开口在 1 秒左右。做法是三段都流式：识别边说边出字，大模型边想边吐字，合成按第一句话就开始念。语音助手用快模型（比如 Claude Haiku、DeepSeek 的快模型这一档），它不需要很聪明，难的事都交出去了。
- **打断**：它在说话时检测到你开口，立刻停止播放，把没说完的部分标成「没说出口」，接着听你说。
- **说得短**：系统提示里规定：一次最多两三句；不念代码、路径、链接、长列表（说「我放在屏幕上了」）；派活前用一句话复述确认（「好，让后端修登录的 bug，修完跑测试，对吧？」），你说「对」才发，或者设置成「直接发」。

### 3.3 和现在的 agent 怎么结合

语音助手是你**在 myco 里的代言人**，用的是你的身份（`@console:<你>`），所以它发出去的任务和你在 App 里打字发的一样：干活的 agent 照常收到、照常 ack、报进展、回复，过程照常显示在对话里。

几个关键点：

- **它写给 agent 的是「整理过的任务」**，不是你的原话录音稿。口语里有重复、口误、「嗯那个」，直接转给 Claude Code 会让它困惑。语音助手把意思整理成一段清楚的任务，结尾附一行「（由语音转述，原话：…）」，agent 需要时能看原话。
- **选对人**：你说「让后端……」，它按成员的名字、分工说明和项目来对上是哪个 agent；拿不准就问你一句。
- **盯进展**：它订阅自己派出去的任务（和 App 现在轮询对话一样），进展、提问、回复来了就进它的「待说」队列。
- **挑时机说**：
  - 你们正在说话：等这轮说完，再说「对了，后端那边好了」；
  - 安静的时候：轻轻一声提示音，然后说一句；
  - agent 在问你（`message ask`）：优先说，因为它在等你；
  - 只是普通进展（「测试跑到一半」）：默认不说，你问「后端怎么样了」才说；可以设置成都说。
- **长任务不占着线**：派完活它就说「交给后端了，好了告诉你」，然后可以聊别的。这正好用上刚做的「先放着」：它不会一直显示在干活。

### 3.4 哪些消息留、哪些不显示

这是你特别提到的。原则是：**干活的 agent 看到的都在 myco 里留着，和现在一样；语音这一层的东西留在「语音」里，不混进 agent 的对话。**

| 内容 | 留不留 | 在哪里看 |
| --- | --- | --- |
| 你说的每句话（识别后的定稿文字） | 留 | 「语音」对话里，一问一答的字幕，可以翻看、搜索 |
| 识别过程中的半句、改来改去的中间结果 | 不留 | 只在说话时实时显示一下 |
| 语音助手说的话 | 留 | 同上，「语音」对话里 |
| 打断后没说出口的部分 | 留，但标「没说完」 | 同上，灰色 |
| 「嗯」「好的」「稍等」这类填充话 | 不留 | 不显示 |
| 语音助手发给 agent 的任务、补充、回答 | 留 | 就在那个 agent 的对话里，和你打字发的一样，带一个小标记「经语音」 |
| agent 的进展、提问、回复、过程 | 留，和现在完全一样 | agent 的对话里；语音里只说摘要，并在「语音」对话里放一个能点过去的链接 |
| 录音本身 | 默认不留 | 不上传、不保存；以后可以加「保存录音」的开关 |

「语音」对话放在哪：先只存在这台电脑的 App 里（和翻译、本地搜索一样），不上 Hub；需要多设备同步时再放到 Hub，做成你自己可见的一个对话。

### 3.5 放在哪、用什么

- **第一版跑在桌面 App 里**，不需要新的服务器：
  - 语音识别：Mac 上用 App 已经接好的苹果语音识别（语音输入用的就是它，能在本机就在本机，支持边说边出字）；Windows 和需要更准的场景，接云端流式识别（比如豆包、Whisper 一类），在设置里选。
  - 大模型：复用「设置 › 翻译」里已经有的 OpenAI 兼容接口配置（地址、模型、钥匙串里的密钥），另选一个快模型给语音用；也可以选 Claude。
  - 语音合成：先用系统自带的（Mac 的 AVSpeechSynthesizer，免费、离线、延迟低），设置里可以换成云端更自然的声音（豆包 TTS 等）。
- **手机**：iOS App 用同一个设计，语音天然更适合手机，放在第二步。
- **说话前后的提示**：开始听时一个短音，开始说时界面上一个会动的波形，你随时可以点一下停。

## 4. 分几步做

1. **按住说话版**（先跑通）：App 里一个「语音」按钮，按住说、松开发；识别 → 语音助手 → 合成；它能派活、补充、回答提问、查进展；「语音」对话留字幕；agent 那边看到的是「经语音」的任务。
2. **免按键、能打断**：VAD 和「说完了没」判断，说话中可以打断，后台进展按 3.3 的规则主动说。
3. **手机和更自然的声音**：iOS 上的语音模式；可选云端识别、云端合成、端到端语音模型；「语音」对话同步到 Hub。

## 5. 还要你定的

- **确认再发，还是直接发**：派活前要不要先复述一句等你说「对」？我倾向默认确认，熟了以后可以关。
- **主动说的程度**：只说完成和提问，还是进展也说？
- **语音助手用哪个模型**：快、便宜、中文好的那一档里挑一个默认的，你有没有偏好（Claude Haiku、DeepSeek、豆包……）？
- **「语音」对话要不要上 Hub**：第一版只在本机，可以吗？
- **先做桌面还是先做手机**：我建议桌面先跑通（识别和模型配置都现成），手机第二步。
