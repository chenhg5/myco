# 做成「客户端」：把用户已有的订阅接进来用（计划）

> 状态：已确认，按第 5 节分阶段做。每做完一项单独发版。

## 1. 定位

用户把自己已有的 Claude Code / Codex 订阅接到 myco 上用：不用开终端，在一个窗口里开对话、看改动、批准操作，出门用手机也能接着管。

对标的两个产品：

- **Cindy**（开源，makecindy/cindy）：桌面端加手机端，授权已付费的 Claude Code / Codex 订阅，手机上能批准操作；登录 Cindy 账号后，经它托管的服务互联。
- **T3 Code**（pingdotgg/t3code）：桌面客户端，背后跑本机已登录的 Codex / Claude Code。新对话默认「完全放开」，可以切到「监督」。

主打**通用 agent**，不只是写代码。

## 2. 原则：只补能力，不改原来的行为

- 多台电脑、导入会话（复制）、交回终端（handover）、ACP 接入、团队成员和权限、端到端加密，都照原样能用。
- 新能力加在现有分层上（harness → runner → hub API → App 后端 → 界面），不另起一套。
- runner 和 hub 不一定同时升级。新的 runner 会报告自己支持哪些新能力（第 4 节），App 只对支持的显示新选项；老 runner 和老 App 遇到新字段，照原来的方式处理。
- 改变默认行为的地方，只对新安装或新建的东西生效。

## 3. 已经定下的

| 问题 | 决定 |
|---|---|
| 手机在外面怎么连 | 用 Tailscale。在家时走局域网；Tailscale 和代理软件在 iOS 上不能同时开，要在界面上写清楚 |
| 推送 | 先不做，保留现在的本地通知 |
| 新对话的默认权限 | 保持现在的默认：只能改它那个文件夹里的文件（workspace）。「完全放开」要那台电脑先允许（`spawn.max_access`），所以不能当默认值（T3 Code 默认完全放开，是因为它只管本机）。对话顶栏加「放开 / 每步都问」开关；设置里可以改新对话的默认档位 |
| Codex 的「每步都问」 | 先不做（要换到 Codex 的 app-server 协议）；Codex 只有「工作区 / 全部」两档，这个选项显示为灰色并写明原因 |
| 要不要 Hub | 保留。简单模式下只监听本机地址，打开 Tailscale 时再加上 Tailscale 的地址 |
| Windows 签名 | 先不做；说明里写清楚首次打开怎么点「仍要运行」 |
| 把 CLI 打包进 App | 不打包。做一键安装，国内网络有镜像或手动步骤兜底 |
| 新对话的文件夹 | 用户可以填；不填就自动建 `~/myco/<对话名>` |
| 简单模式下的团队功能 | 藏起来，用户「邀请别人」时再出现 |

## 4. 地基：runner 报告支持的能力

runner 本来就会报告 CLI、版本、模型（`api.Runtime`）。在里面加 `features []string`，列出这台 runner 支持的新能力：

| 名字 | 含义 | 来自 |
|---|---|---|
| `agent_status` | 能报告本机 CLI 装没装、登没登录 | 第 5.1 节 |
| `offline_reason` | 停下时会说原因 | 第 5.3 节 |
| `changes` | 每轮会上传改了哪些文件 | 第 5.5 节 |
| `ask_access` | 认识「每步都问」这一档权限 | 第 5.6 节 |

hub 原样存、原样返回，不做判断。App 拿到才显示对应的东西；没有这个字段就当什么都不支持。

## 5. 分阶段

### 第 1 周

**5.1 本机 agent 的状态、安装、登录**

- harness 的 `Check` 现在会查「装没装、版本多少」，这次加上「登没登录」，并且不花额度。Codex 用 `codex login status`；Claude Code 看凭据在不在（钥匙串或配置目录里的凭据文件）。查不出来就记为「未知」：不能因为查不出来就说没登录，挡住用户。
- App 后端新增 `GET /app/local/agents`：本机每个 CLI 的状态（没装 / 没登录 / 可用 / 未知）、路径、版本。PATH 用现在的终端 PATH 探测（`LoginShellPath` 和 `agentDirs`）。
- **安装**：优先用官方的安装方式，其次 npm；显示正在跑的命令和输出；失败时给手动步骤。
- **登录**：在 App 的终端里跑 `claude` 或 `codex login`，复用现在终端的界面；关掉终端后重新检查。
- 报错说人话：没装、没登录、订阅过期、额度用完（几点恢复）、版本太旧，每种都给一个下一步。

**5.2 新开对话时的选项**

- 「新开一个」的「更多选项」里加上模型、思考强度、权限（只读 / 这个文件夹 / 完全放开，默认「这个文件夹」，和以前一样）。权限随新开会话的请求一起发（`spawn` 本来就收 `access`）；模型和思考强度在建好后写进现成的 `RunSettings`（v0.19.5 起就有），不用新接口。
- 模型列表：内置一份常用的（Claude 的别名、Codex 的模型名），永远可以手动输入。
- 文件夹可以不填，不填就建 `~/myco/<分工>`，没填分工就是 `~/myco/<CLI>-<月日>-<时分>`。只有 v0.20.11 之后的电脑会建（machine node 只建 `~/myco/` 下一层、不存在的文件夹，别处不存在照样拒绝）；更老的电脑上文件夹还是必填。
- 不选的项跟着这台电脑的设置走，就是现在的行为。

**5.3 离线时说清楚原因**

- runner 停下时告诉 hub 原因：用户停的、服务被停、系统关机。App 收到 macOS 的睡眠通知时也报一次。在 WSL 里跑的 runner 要标明自己在 WSL 里。
- hub 记下「最后一次看到」的时间和原因，App 显示成「这台电脑 10 分钟前睡着了」，并说明消息会排队，醒来后接着做。
- 原因是可选字段：老 runner 不报，就和现在一样只显示「离线」。

### 第 2 周

**5.4 一个人用的「简单模式」**

- **只对新安装生效**：从欢迎页「在这台电脑上开始」一键启动后，App 进入简单模式（App 自己的设置，存在这台电脑上）。已经有工作区的用户打开还是完整模式，什么都不变。
- 简单模式只是**藏起来**，不删也不改任何东西：侧栏的「电脑」，工作区切换器里的「加入 / 新建工作区」，设置里的「工作区 / 成员 / 审计」，添加 agent 里的「发一句话」（接别处的 agent）。对话、agent、项目、自动化、应用照常。
- 设置 › 外观里有「简单模式」开关，关掉就是完整模式。
- 和计划的出入：原计划让简单模式下的本机 Hub 只监听 127.0.0.1。但 App 本来就会把本机 Hub 搬到局域网上（`lanfix.go`，为了别的电脑和手机能加入），改成只听本机会和这个机制冲突，也会让「加电脑」那一步更容易出错。所以这一版**不改 Hub 的监听地址**，只改界面；首次打开时 macOS 的「允许传入连接」弹窗还会出现。
- 还没做：启动后列出检测到的 agent 让用户勾选（现在是在「添加 agent」里加：「这台电脑上的」会话，或者「新开一个」，没装、没登录的 agent 那里有安装和登录按钮）。

**5.5 看改动**

- runner 在每轮开始和结束时，在工作目录里各跑一次只读的 `git status` / `git diff`，作为新的过程事件 `changes` 上传：改了哪些文件、每个文件的 diff。有大小上限，太大就只给文件列表。
- 工作目录不是 git 仓库时，从 agent 的编辑步骤里拼：Claude 的 Edit/Write 带着改前改后的内容，Codex 的 apply_patch 带着补丁。（第一版先不做：非 git 目录不显示改动。）
- 实现：运行前 `git stash create` 记下工作区（只写一个提交对象，不动文件、索引和引用；没有未提交改动时用 HEAD），并记下已有的未跟踪文件；运行后和它比，加上新出现的未跟踪文件。每个文件一个 `change` 过程步骤（`tool` 路径、`input` A/M/D/R、`added`/`removed` 行数、`output` diff，单个最多 12KB），最多 50 个，多出来的用一个 `text: "+N"` 的步骤说明。同一个文件夹里同时跑多个任务时，改动会混在一起。
- App 在每一轮下面显示「改了 N 个文件」，点开看 diff。
- 撤销和提交会改用户的文件，放到后面做，并且要二次确认。
- 兼容：老 App 遇到不认识的事件类型要跳过，这一点要确认并加测试。

### 第 3–4 周

**5.6 「每步都问」**

- 新增第四档权限 `ask`。agent 要做超出权限的事时，runner 把请求变成对话里一张「待批准」卡片，复用现有的「agent 提问、发消息的人回答」（`message ask`）。用户点「允许 / 拒绝 / 以后都允许」，回答再交回给 agent。
- 先做 ACP 接入的 agent：`acp/policy.go` 里本来会自动拒绝的请求，改成去问人。再做 Claude Code：用 `--permission-prompt-tool`，runner 提供一个小的 MCP 工具，等用户回答。Codex 暂不支持。
- 没人回答时，到时间按「拒绝」处理，并告诉 agent，让任务不会一直挂着。时长可以配置。
- 对话顶栏加「放开 / 每步都问」开关；设置里可以改新对话的默认档位，默认还是「这个文件夹」（workspace）。
- 兼容：已有 agent 的权限不变。老 runner 不认识 `ask`，所以 App 只对报告了 `ask_access` 的 runner 显示这一档，hub 也拒绝给老 runner 设这一档。
- 风险：
  - 等批准时任务是卡住的，要确认运行时限、「会话在用」的判断不会把它当成卡死。
  - 会话交回终端后，审批走 CLI 自己的界面，两条路不能冲突。

### 第 4–5 周

**5.7 手机在外面用**

- App 里加「让手机在外面也能连」：检测本机有没有 Tailscale，Hub 多监听一个 Tailscale 地址，生成用 Tailscale 地址的手机加入链接。Tailscale 的接入已经有了，主要做引导。
- 在家时手机走局域网；在界面上写明 iOS 上 Tailscale 和代理软件不能同时开。
- iOS：上 TestFlight（`ios/scripts/testflight.sh`），加审批卡片和扫码加入。
