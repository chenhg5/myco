# 模板与套件：让网页成为人和 agent 一起用的工具（讨论稿）

> 叫法：App 和文档里对人统一叫「应用」（官方应用、这个工作区的应用、最近建的）；命令行、API、清单文件里还叫 template（`myco template`、`/v1/templates`、`myco.json`），不改名，免得旧的 runner、agent 和脚本失效。这篇设计稿里的「模板」就是界面上的「应用」。

> 状态：第一步、第二步已做（v0.20.5）：网页的记录和变化流、工作区里的模板库、`myco template` / `myco page data`、桥的 `myco.data.*` 和 `myco.download`；官方应用随 Hub 提供（办公套件、编程开发、效率工具、生活、创意设计、游戏，共 15 个）；App 边栏的「模板」。不做市场。

有了 App 里的网页（[browser.md](browser.md)）和 myco 桥，很多办公的东西都能做成网页：表格、多维表格、文档、幻灯片、表单、看板。思路是不让 agent 每次现写一个网页，而是做好**模板**，agent 和人都只往里写**数据**；用户也能自己做模板、上架、分享。

## 1. 三个概念

- **模板**：做好的网页。一个文件夹：网页文件 + `myco.json` 清单（名字、版本、数据结构、要的权限、给 agent 的说明）。不含任何人的数据，可以上架、分享、升级。
- **实例**：一次具体的使用 =「某个模板的某个版本 + 一份数据」。比如「Q4 招聘进度表」是「多维表格」模板的一个实例。放在项目或对话里，能置顶，人和 agent 都能打开、改数据。
- **套件**：几个模板 + 配套的 agent 技能 + 自动化，一次装好。官方的「工作套件」「编码套件」，或者用户自己做的「招聘套件」。

## 2. 整体架构

```
 人 · myco App                    工作区 Hub                          agent · 它的电脑
┌──────────────────────┐   取模板  ┌──────────────────────────┐        ┌──────────────────────┐
│ 实例网页（沙箱 iframe） │ ───────▶ │ 模板库：模板按版本存 zip    │        │ myco CLI              │
│ 只通过 myco 桥读写数据  │          │ 清单、权限、给 agent 的说明 │        │ app new / data get    │
│ 导出 Excel / PDF / PPT │          ├──────────────────────────┤  CLI   │ data patch / watch    │
├──────────────────────┤   读写   │ 实例和数据                 │ ◀────▶ │ template init/publish │
│ myco 桥                │ ◀──────▶ │ 集合 → 记录（按行改、带版本）│        ├──────────────────────┤
│ data · subscribe ·     │          │ 变化流、按清单校验、权限    │        │ 模板给它的说明（agent.md）│
│ send · download        │          ├──────────────────────────┤        ├──────────────────────┤
├──────────────────────┤          │ 文件：图片、附件、导出       │  叫醒  │ 连接器技能（可选）      │
│ App 后端（console）    │          │ 通知：人改了 → 合并成一条消息 │ ─────▶ │ 飞书 / 钉钉，用户的凭证  │
└──────────────────────┘          └──────────────────────────┘        └──────────────────────┘
                                         ▲ 装进来
                                  模板市场（以后）：官方套件、用户上架的模板
```

人和 agent 不碰对方的东西：人用网页，agent 用 CLI，两边改的是 Hub 上同一份数据。模板只管怎么显示，数据和权限在 Hub。

## 3. 一次改动怎么流动

1. 人在网页里改了一行：patch 第 12 行，基于第 41 版。
2. Hub 记成第 42 版；agent 在 `data watch`，收到变化（agent 没开着时，Hub 防抖后合并成一条消息叫醒它，内容只是数据）。
3. agent 补了数据：patch，基于第 42 版。
4. Hub 记成第 43 版；开着的网页订阅了变化，马上显示「agent 改了」。
5. 两边同时改同一行：后到的收到冲突和最新值，合并后再交。不同行互不影响。

## 4. 用户自己做模板

说出来（「帮我做个周报模板」，agent 用 `myco template init` 起脚手架）→ 边做边看（`myco page serve` 实时预览，用示例数据试，提意见它改）→ 发布（`myco template publish`，进工作区的模板库）→ 分享（工作区里的人都能用；分享链接给别人装；上架市场）→ 升级（发新版本，实例提示「有新版本」，数据按 `dataVersion` 迁移）。做模板不需要会写代码。

```
weekly-report/
├─ myco.json      清单
├─ index.html     界面（任何前端框架构建出来的都行）
├─ agent.md       给 agent 的说明：数据结构、怎么填、注意什么
└─ sample.json    示例数据（预览、市场截图）
```

```json
{
  "id": "glenn/weekly-report",
  "name": "周报",
  "version": "1.1.0",
  "kind": "doc",
  "data": {
    "items": { "fields": { "title": "text", "owner": "person", "done": "bool", "due": "date" } },
    "summary": { "single": true, "fields": { "text": "markdown" } }
  },
  "dataVersion": 2,
  "migrate": "migrate.js",
  "permissions": ["send", "download"],
  "export": ["xlsx", "pdf"],
  "agent": "agent.md"
}
```

## 5. 权限和安全

| 能力 | 默认 | 说明 |
| --- | --- | --- |
| 读写自己实例的数据 | 有 | 只能是这个实例，按清单的结构校验 |
| 以你的名义发消息（send） | 要声明 | 第一次发时问一次，和现在的网页一样 |
| 存文件到下载（download） | 要声明 | 导出 Excel / PDF 用 |
| 连外网（net） | 没有 | 要声明具体域名，经 Hub 转发，装的时候列出来 |
| 读别的实例、对话、令牌 | 永远没有 | 沙箱隔离，不同源 |

- 官方模板签名，市场里标「官方」；第三方模板标作者，上架前审核，装的时候列出它要的权限。
- 人在网页里写的东西，到 agent 那里都是数据，不是指令。
- 开了端到端加密的工作区先不开放（数据明文存在 Hub 上，和网页一样）。

## 6. 官方套件（第一批的想法）

- **工作套件**：表格（列有类型，筛选排序，导出 CSV / Excel）、多维表格（同一份记录，表格 / 看板 / 日历 / 画廊几种视图，表单收集）、文档（块编辑器，导出 Word / PDF）、幻灯片（agent 写大纲，自动排版，导出 PPT / PDF）；技能：飞书、钉钉同步（用你自己的凭证）。
- **编码套件**：任务看板、测试报告、代码评审（逐条批注，agent 改完打勾）、发版清单、设计预览（开发服务器的实时预览 + 批注）。

导出在模板里用浏览器端的库做（SheetJS / ExcelJS、docx.js、PptxGenJS，PDF 用系统打印），通过桥的 `download` 存到「下载」。数据本身是结构化的 JSON，agent 也能自己导出。

## 7. 和现在的东西怎么接

- 网页（已有）：实例就是一种网页，沿用沙箱、面板、标签、置顶、版本。
- 共享状态（已有，整份 JSON，最多 256KB）→ 升级成「集合 / 记录」，按行改、有变化流；老网页照常用。
- myco 桥（已有 ready / update / on / send / storage）→ 加 `data.*`、`subscribe`、`download`、`export`。
- 置顶（已有）：实例可以置顶到对话和项目。
- 手机：网页已经能在 iOS 里开，桥要补上。

## 8. 分几步做

1. 数据层（集合、记录、按行改、变化流、agent watch）、桥的 data / download、工作区内的模板库、`myco template init / publish`、`myco app new`。做完：用户让 agent 做模板，在自己工作区里用、给同事用。
2. 官方工作套件：表格、多维表格、文档；导出 Excel / PDF；实例置顶和项目里的入口。
3. 分享链接安装、版本升级和数据迁移、权限确认、编码套件、幻灯片。
4. 模板市场（官方 + 上架审核）、飞书 / 钉钉连接器、多人同时编辑文档（Yjs）。

## 10. 官方模板（第二步，已做）

随 Hub 一起提供（`internal/templates/official`，编进二进制），每个工作区的模板库里都有、排在最前、标「官方」，不能删，跟着 Hub 升级；`myco/` 开头的 id 留给它们。v2 对标飞书：源码在仓库的 `templates/`（React + Vite，`make templates` 构建进 `internal/templates/official`，构建结果提交进仓库，Go 构建不跑 Node），共用 `templates/src/_lib`（桥的封装：按顺序存一个集合、别人改的实时合进来、冲突时换成最新的、同一条记录的写入排队；CSV 和不依赖任何库的 .xlsx 生成）。浅色、深色都有，不连外网。用模板建的网页带着当时的文件副本，升级 Hub 不会改已经建好的网页。

- **表格**（`myco/table`，v2）：表格用 [Glide Data Grid](https://github.com/glideapps/glide-data-grid)（MIT，canvas 绘制，几万行也流畅）。`sheet`（一条 main：标题、列；列可带 `width`）+ `rows`（每行 `cells` 按列 id 存、`order`）。列类型：文本、多行文本、数字、单选、多选、日期、勾选、人员、链接；单选和多选是彩色标签，在格子里点开就能选、搜索、新建选项（新值自动加进选项）。框选、复制、从 Excel 粘贴一块（超出的行自动新增）、拖填充柄往下填、Delete 清空；拖列宽、拖动列和行换位置、冻结首列；列头菜单：改名、改类型（文本改成单选时，已有的值变成选项）、编辑选项（改选项名会同步改已有的值）、排序、左右插入、删除；右键行：上下插入、删除（可撤销）；筛选（多个条件，全部或任一）、排序（多个字段）、Ctrl+F 搜索，只在这个人的浏览器里记着，不影响别人；导出 Excel 和 CSV（按当前筛选和排序）。
- **多维表格**（`myco/base`，v2）：同一套表格，加上视图：看板（按单选字段分组，拖卡片改值、调顺序，每列能直接新建）、日历（按日期字段，拖到另一天改日期，每天能新建）、画廊、表单（填好提交就是一条新记录）。点一条在右侧展开（表格里把鼠标放到第一列点展开图标，或右键「展开记录」），所有字段都能改，上下切换、删除。`base`（一条 main：标题、字段）+ `records`（`values` 按字段 id 存、`order`）。
- **文档**（`myco/doc`，v2）：对标飞书文档，编辑器用 [BlockNote](https://www.blocknotejs.org/)（MPL-2.0，基于 ProseMirror），`doc`（一条 main：标题）+ `blocks`（每个顶层块一条：`type` p / h1–h3 / li / ol / todo / toggle / quote / code / hr / table、`text` 纯文字、`checked`、`order`，`block` 是编辑器自己的完整格式：加粗、颜色、链接、嵌套、表格）。「/」菜单插入各种块，`#` `-` `1.` `[]` `>` 等 Markdown 快捷写法，选中文字出格式工具条，左侧把手拖动调整段落；停顿 0.5 秒保存，只写改了的块，两个人改不同块互不覆盖；agent 只写 `type` 和 `text` 也行，网页据此画出来；导出 Markdown 和网页。
- **幻灯片**（`myco/slides`）：按版式自动排版，不做自由拖拽（agent 好写、做出来不丑；以后再在版式之上加自由文本框和形状）。`deck`（一条 main：标题、主题 light / navy / warm / tech）+ `slides`（每页一条：`layout` cover / section / points / two / cards / chart / table / quote / end，`title`、`subtitle`、`points`、`body`、`cards`、`chart`（柱状、折线、饼图）、`table`、`notes`、`order`）。左边缩略图拖动换顺序、复制、删除（可撤销）；中间点哪改哪（要点里回车新起一条，空的退格删掉）；右边换版式、编辑图表数据和表格行列、换主题；演讲者备注；全屏放映（方向键、空格、点击翻页）；导出 PowerPoint（pptxgenjs，MIT：文字、卡片、图表、表格、备注在 PowerPoint 和 WPS 里都能接着改）和 Markdown 大纲。

**黑白灰**：官方应用的界面不用蓝色这类高亮色：强调色（主按钮、选中、勾选、焦点、进度）浅色里是近黑 `#1f2329`、深色里是近白 `#e6e6e6`，上面的字用 `--on-accent`（`templates/src/_lib/sheet.css`，表格的 Glide 主题在 `_lib/grid.tsx`）；记账本的分类图、思维导图的分支、视频剪辑的片段和时间线也是灰阶。数据本身的颜色照旧：单选多选标签、人员头像、白板便签、幻灯片的「深蓝」「暖色」「科技」主题和图表系列（「简约白」主题改成了黑白灰）、日历按选项分的颜色、收入绿支出红。

**按类上架**（v0.20.6）：myco.json 的 `category` 决定它在 App 应用页的哪一栏：`office` 办公套件、`dev` 编程开发、`tools` 效率工具、`life` 生活、`creative` 创意设计、`game` 游戏、`other` 其他。旧 Hub 没有这个字段，App 按 `kind` 把表格、多维表格、文档、幻灯片放进办公套件。图标统一一个中性样式（浅灰底、深灰线条），靠图标本身区分。除了上面四个办公套件，官方还有：

- **编程开发**：**代码编辑器**（`myco/code`）：Monaco（VS Code 的编辑器，MIT），`project` + `files`（每个文件一条：`path`、`content`，一个文件 60KB 以内）；文件树、多标签、语法高亮、查找替换、多光标、小地图，停顿 0.8 秒或 Ctrl+S 保存，别人改的直接进来（自己正在改的那个文件除外）；HTML 带上它引用的本地 CSS、JS 预览，Markdown 也能预览；整个项目下载成 zip。**开发者工具箱**（`myco/devtools`）：JSON、Base64、URL、MD5/SHA、时间戳、UUID、JWT、正则、文本对比、命名、进制、颜色，全在页面里算；`saved` 是大家共享的收藏，agent 也能往里放（写好的正则、要看的 JSON）。
- **效率工具**：**待办清单**（`myco/todo`）：`tasks`（标题、做完、截止、负责人、重要、备注、order）；回车就加，认得「明天」「周五」「@名字」「!」，全部、我的、今天、重要。**投票**（`myco/poll`）：`poll`（问题、选项、单选多选、匿名、结束）+ `votes`（每个投票人一条，id 由名字算出来，再投就是改票），结果实时更新。
- **生活**：**记账本**（`myco/ledger`）：`book`（币种、月预算）+ `entries`（收支、金额、分类、备注、日期）；按月看支出、收入、结余、预算剩余，分类占比的环形图，按天列，导出 CSV。**习惯打卡**（`myco/habit`）：`habits` + `checks`（每次打卡一条，id 是习惯、日期、人拼起来的，重复打卡还是同一条）；每人给自己打卡，看这周、连续天数，别人的卡是小圆点。
- **创意设计**：**白板**（`myco/whiteboard`）：`items`（便签、文字、矩形、椭圆、连线；位置、大小、文字、颜色、层级），拖动、调大小、缩放平移，没给位置的自动排成格子，导出 SVG。**思维导图**（`myco/mindmap`）：`nodes`（文字、父节点、order、折叠），Tab 子主题、Enter 同级、拖到别的主题上就挪过去，导出 Markdown 大纲。**视频剪辑**（`myco/video`）：视频文件只存在打开它的电脑上（网页自己的 IndexedDB，按文件大小和首尾 256KB 算出的指纹认文件），Hub 上只存剪辑方案：`project`（标题、画面比例、背景色）、`media`（导入的文件：名字、时长、宽高、有没有声音、指纹、一张小封面）、`clips`（主轨道，按 `order` 首尾相接：哪个文件的 `in`–`out`、`speed`、`volume`、`muted`）、`overlays`（时间线上 `start`–`end` 的文字、模糊、马赛克，位置是占画面的比例，`lane` 是第几行）、`notes`（某个时间点的备注，`done`）。时间线：缩略图和声音波形，拖动调顺序、拖两端裁剪、S 分割、复制，⌘+滚轮缩放，边缘和播放头互相吸附；画面上拖动文字和打码框、拖四角改大小；变速 0.25～4 倍（导出时声音用 WSOLA 变速不变调，和播放时一样）；撤销重做。导出前选分辨率（不超过原片：4K、2K、1080p、720p、480p）、帧率（24、30、60）和画质（最高、高、标准、小文件），能看到画面尺寸和大概的文件大小，选择记在这台电脑上；导出时显示已用时间和还要多久；App 的桥带 `myco.features`（v0.20.27 起有 `download-media`：能存视频），旧 App 在导出前就提示先更新 App；存到「下载」失败时做好的视频留在框里，能「再存一次」或「用浏览器下载」，不会假装存好了。导出的 mp4 边做边写进网页自己的磁盘存储（OPFS；没有时才放内存），声音每 10 秒混一段，不再整段放进内存：5 分钟 1080p 导出 223 MB，网页的 JS 内存最多 23 MB。解码下一帧和编码上一帧同时进行，原片的帧按顺序解一遍，不按时间点去找。导出 mp4 在浏览器里完成（[mediabunny](https://mediabunny.dev)，MPL-2.0，WebCodecs 编码 H.264，声音 AAC，没有就 Opus；两样都没有的浏览器按需加载 FFmpeg 的 AAC 编码器（WebAssembly，LGPL-2.1）），播放和导出用同一段画图的代码。换一台电脑或换了文件，素材上提示「本机没有，选文件」，选到同一个文件自动对上，不同的文件先问一句。agent 看不到画面：它读备注、改记录（`agent.md` 有分割、加字幕、加打码的例子），改完把备注标成已处理；网页的「交给 agent」给出一段可以直接发给 agent 的话。App 从这版起记住给网页用的端口（`hubs.json` 旁边的 `page-port`），重启后网页还是同一个源，存在浏览器里的视频不会丢。
- **游戏**：**五子棋**（`myco/gomoku`）：`game`（谁执黑、谁执白、第几局）+ `moves`（每一手一条，id 是「局-手数」，两个人同时下同一手只有一个能成功），网页管轮次、判五连，人和 agent 都能下。**数独**（`myco/sudoku`）：`puzzle`（题目、难度、第几题）+ `cells`（每填一格一条），谁填的是谁的颜色，冲突标红，网页生成只有一个答案的新题。

**官方应用和 Hub 解耦**（v0.20.7）：
- **单独发布**：构建好的官方应用（`internal/templates/official`）一有变化，GitHub Actions（`.github/workflows/apps.yml`，打包脚本 `scripts/pack-apps.sh`）就更新一个叫 `apps` 的发布：`apps.zip`（一个应用一个文件夹）和 `SHA256SUMS`。它是预发布，不是 latest，`myco upgrade` 和 Hub 的升级检查都不看它。
- **Hub 自己拉**：Hub 启动 20 秒后、之后每天拉一次（`myco template sync` 或应用页的「检查官方应用更新」立刻拉，最多一分钟一次），按 `SHA256SUMS` 校验，每个应用按模板的规矩检查；同一个应用取二进制里的和拉到的里版本高的，新应用直接加上。拉到的存在数据库旁边（`official-apps.zip`），重启不用等网络。关了升级检查（`--no-update-check` 或 `MYCO_NO_UPDATE_CHECK=1`）就只用二进制里带的和存下来的，内网、离线的 Hub 照样有官方应用。
- **最低 Hub 版本**：myco.json 的 `requires.hub`；Hub 先只读这一项，太旧就跳过这个应用（它的 manifest 可能有旧 Hub 不认识的字段），等升级。
- **应用自带图标和分类**：`icon`（应用里的一个 SVG）和 `category`，App 不写死任何应用；技能也不列名单，让 agent 用 `myco template list` / `get`。
- **给 agent 的是一层层的**：技能里只有一小段通用的用法；`myco template list` 默认每个应用一条（id、名字、一句说明、分类，不带图标、数据结构、版本和说明，15 个应用约 6KB，带 `--full` 才是全部字段，约 23KB），可按 `--category`、`--query` 筛；选中一个再 `get` / `use` 拿它自己的 `agent.md`（每个 0.6～2KB，最多 32KB）。应用再多，agent 每次读到的也只是一张短名单加一份说明。
- **建好的网页升级**：用应用建的网页带着当时的文件；应用出了新版本，网页面板顶上提示「有新版本，升级后数据不变」，点「升级」（或 `myco page upgrade --page`）就换成新版本的文件和数据结构，记录原样保留。

每个模板都带 `agent.md`（怎么读写它的数据）和 `sample.json`（示例数据）。

**App 里的入口**：边栏「自动化」下面一行「应用」。页面上先是官方应用，按类分栏（办公套件、编程开发、效率工具、生活、创意设计、游戏），再是「这个工作区的应用」（没有时说一句怎么让 agent 做一个），最后是「最近建的」网页（点开就在网页面板里）。点一张卡片：填名字、选放在哪个项目（或不放进项目）、要不要先放示例数据，点「新建」（对话框标题是「新建一份表格」这样），网页在面板里打开。
