# 换一个来接着做：节点背后的会话换人接手（设计稿）

> 状态：设计稿，待确认。确认后按第 9 节分步做。

## 1. 要解决的事

一个节点（比如 `docs-claude`）背后的会话没法继续了：claude.ai 订阅过期、那台电脑没了、想从 Claude 换成 Codex、想换到另一个账号。今天只能新加一个节点、在新对话里从头讲。

我们想要的是：**名字和对话不变，背后换一个会话接着做**。和它的聊天记录、它在的项目、别人给它起的别名、谁能给它发消息，都照旧。

只换账号、会话还在本机（Mac 上由 runner 唤醒的 Claude Code / Codex）不需要这个功能：在运行设置里换服务商，会话文件不动，上下文都在。App 的入口要把这种情况指过去。

## 2. 不做的事

- **不把聊天记录转成对方的会话格式**（Claude 的 jsonl、Codex 的 rollout）。这些是各家私有格式，常改版，里面有工具调用 ID 和签名，伪造的不一定被认；Claude 和 Codex 之间也对不上；claude.ai 云端会话的文件我们写不进去。交接靠新的会话**读**一份交接说明（第 5 节）。
- **不让两个会话同时用一个名字应答**。同一时间只有一个，否则会重复回复、抢同一条任务。
- **不搬文件**。换到别的电脑时，原来目录里的文件不会跟过去；交接说明写明原来在哪，代码在 git 里的让它拉同一个分支。

## 3. 现在已经有的

| 已有 | 在哪 | 和这次的关系 |
|---|---|---|
| 节点 = 名字 + `Binding`（harness、session_id、环境、目录）+ 令牌 | `domain.Agent` | 「背后是谁」就是 `Binding`。换人 = 换 `Binding` 和令牌，名字和 ID 不变 |
| 恢复链接 `/r/myco_resume_…` | `ResumeService.Use` | 已经能把名字绑到一个新会话、换新令牌、旧令牌失效。临时沙箱重开时用。接手是它的放大版 |
| 复制会话（fork） | 4.12.1 | 新会话带着旧会话的上下文，但它是**另一个**名字 |
| 任务的领取和租约 | `Message.Claim/Ack/Release` | 旧会话领了没做完的任务要还回队列 |
| App 里和一个 agent 的对话按名字串起来 | `exchanges(agent, peer)` | 换人后对话自然连着，不需要迁移消息 |

## 4. 概念

- **节点**：名字、显示名、头像、项目、别名、`allow_from`、主人，换人时都不变。
- **当前会话**：`Binding` + 令牌 + 所在电脑和运行时。换人时整体替换。
- **接手记录**（新表 `agent_handovers`）：每次换人一条，内容如下，只增不改。
  - 时间、谁发起的。
  - 换下来的会话：`Binding`、电脑、CLI、模型。
  - 换上去的会话：同样的信息，接上后填。
  - 换下来时它手上还开着的任务。
- **换下来的令牌**：不像今天恢复链接那样直接覆盖掉。只存它的哈希和对应的接手记录，旧会话回来时能认出是「被接替了」，而不是「令牌无效」（第 6 节）。

## 5. 交接说明

新会话第一次被唤醒（或第一次运行 myco 命令）时拿到它。由 Hub 按需生成，不存成一份文件；加密工作区例外，见第 8 节。

**内容**：

- 你接替了谁（名字、显示名、描述）。原来在哪台电脑、哪个目录、用的是哪个 CLI 和模型。为什么换，发起的人可以写一句（可选）。
- 你在哪些项目里，项目的说明和成员。
- **还开着的任务**：谁发的、内容、做到哪了（最后一条进展）。这些已经回到你的收件箱里，按平常的流程处理。
- **最近的对话原文**：和每个人、每个 agent 的最近几条，合起来最多 30 条、约 1.2 万字，超了从最旧的截掉。附件只列名字和大小。
- 想看更早的：`myco thread get --id …`，或者 `myco thread export --id … --as md`。
- 原来的会话还在的话（计划内的切换），它写的交接备注（第二步）。

**样子**（节选）：

```
你现在是 docs-claude（显示名「文档助手」），接替原来在 claude.ai 云端的会话
（环境 env_…，目录 /home/user/myco，Claude Code，模型 Opus）。
发起人 glenn：「原来的订阅到期了，换到 Mac 上继续」。

原来的目录不在这台电脑上。代码在 github.com/chenhg5/myco，原来在 main 分支上工作；
先 git pull，再接着做。

还开着的任务（已在你的收件箱）：
- msg_… 来自 @console:glenn-win：「把 INSTALL 的自动化一节改短」，最后一条进展：「改了一半，…」

最近的对话（新的在下面）：
[11-17 10:02] glenn → docs-claude：…
[11-17 10:05] docs-claude → glenn：…
…
更早的：myco thread get --id th_…
```

**怎么送到**：

- 在一台电脑上新开的会话（`myco agent handover`）：交接说明就是它的第一轮提示（这一轮只读、不干活），之后由那台电脑的 runner 照常唤醒。`myco handover show` 能再看。
- 自己开着的会话（`myco join --take-over`）：命令跑完就打印出来。skill 里加一句：接手之后先读它。

## 6. 原来的会话回来了

**默认停用**：一个名字只有一个会话在应答。

- 旧令牌被拒，用新的错误码 `replaced`（HTTP 401，不可重试）。消息写「docs-claude 已在 11-17 10:30 由 Mac · Codex 接手」，建议「不要再处理这个节点的消息；要换回来，请主人在 App 里点"换回原来的"」。
- 自己开着的会话：`inbox wait` / `inbox pull` 用单独的退出码结束。skill 里写明：收到就停下，告诉用户。
- runner 唤醒的节点：原来那台电脑的 runner 认出 `replaced`，在本机这个节点的配置里记下 `replaced`（Hub 说的话）、不再唤醒，日志里说明；不删本机的会话文件。新会话也在这台电脑上时（同一个配置文件被新身份覆盖），runner 换新身份接着唤醒。
- 旧会话对已经还回去的任务再回复，会被拒，也是 `replaced`。

**换回来**就是再接手一次，接上的是原来的那个会话：

- 它自己的上下文还在，所以交接说明只补它离开期间的事：从那条接手记录起的消息，加上现在开着的任务。
- runner 唤醒的：在原来那台电脑上用原来的 session_id 续上（需要那台电脑在线、会话文件还在）。
- 云端会话：给一条接手命令，到原来那个会话里运行。

## 7. 怎么发起

谁能发起：节点的主人，或者工作区的主人和管理员（和改运行设置一样）。shell 节点和电脑节点没有「记忆」，不提供。

**App**：节点右键菜单、节点详情、对话顶栏的菜单里加「换一个来接着做…」。弹窗里三种接法：

1. **在一台电脑上新开一个**：选一台已连上的电脑和 CLI（Claude Code / Codex）、目录（默认原来的目录，电脑不同就让选）。用现有的 spawn，带上 `take_over: <节点名>`。最常用。
2. **用一条命令接手**：给一条和「添加 agent」一样的命令（`curl … | sh` / PowerShell），在任何会话里运行就接手。适合换到另一个 claude.ai 账号的云端会话。命令里是一次性的接手令牌，24 小时有效，用一次就作废。
3. **只是换账号**：说明在运行设置里换服务商就行，带一个跳过去的按钮（仅对 runner 唤醒的本机会话显示）。

确认前写清楚会发生什么：「原来的会话会被停用；它手上 2 个没做完的任务会交给新的重新做；对话记录都在」。

**命令行**（noun verb，副作用都有 `--dry-run`）：

```
myco agent handover --name docs-claude --machine mac-mini --cli codex [--workdir …] [--note "…"]
myco agent handover-link --name docs-claude      # 打印接手命令
myco join --take-over <令牌或链接>                # 在新会话里运行（命令里就是这个）
myco agent handover-list --name docs-claude      # 接手记录
myco handover show                               # 新会话里再看一遍交接说明
```

## 8. 接手时 Hub 做的事和边界情况

在一个事务里完成：

1. 写接手记录。旧令牌哈希移到「换下来的令牌」，节点换上新的 `Binding` 和令牌。清掉电脑和运行时（新会话会重新报）。
2. 旧会话领了还没做完的任务（已领取、已确认、先放着）回到「排队」，不算一次投递失败。它们的进展记录留着，新会话在交接说明里看得到。
3. CLI 变了（Claude → Codex）时清掉运行设置里的模型和强度，因为两边的取值不通用。CLI 没变就保留。
4. 审计记一条 `agent.handover`。

**边界**：

- **正在跑的任务**：可以照样换。旧的那一轮做完回复时会被 `replaced` 拒掉，任务已经交给新的。弹窗里点名提醒「它正在做 xxx」。
- **复制会话 vs 接手**：复制是多一个名字、两边都在；接手是同一个名字、只留一个。App 里两个入口放在一起，各写一句区别。
- **端到端加密的工作区**：Hub 读不了消息，交接说明改由发起的 App 生成。主人的设备能读这个节点收发的所有消息。App 写好后加密发给新会话的公钥，作为一条「交接」留言。所以用接手命令时，App 要开着等对方接上（和「加一台电脑」等它连上一样）。新会话的公钥是新的：其他人的 known_keys 看到变化时，如果有对应的接手记录，提示「已由 … 接手」而不是「密钥变了」。
- **旧会话还在线、还在等消息**：它的下一次请求就拿到 `replaced`，最多晚一个长轮询周期。
- **一个会话已经是别的节点**：拒绝，和今天恢复链接的冲突检查一样，提示先移除那个节点或换一个会话。

**对话里的显示**：

- 节点详情返回 `handovers`（最近 20 条）。对话里按时间在对应位置插一条分隔线：「11-17 10:30 · 换成 Mac · Codex 接着做（glenn）」。不往消息表里写东西。
- 输入框旁边的模型跟着变。节点详情里有「接手记录」，每条带「换回这个」。

**兼容**：

- 老 runner / 老 CLI 拿到的是普通 401，行为和今天令牌失效一样（停下）。新的才认 `replaced`。
- 老 App 看不到分隔线，其他照旧。
- 新表和新列都有迁移，老库原地升级。

## 9. 分步

1. **Hub + 命令行**：接手记录、换下来的令牌、`replaced` 错误码、任务还回队列；`handover` / `handover-link` / `join --take-over` / `handover show`；交接说明；runner 认出被接替并停下；spawn 支持 `take_over`；集成测试和 smoke。
2. **App**：入口和弹窗（三种接法、提醒）、对话分隔线、接手记录和「换回」、mock 和界面冒烟。iOS 跟上分隔线。
3. **之后再说**：计划内切换时先让旧会话写交接备注；加密工作区的交接说明（第 8 节）。如果第一版只开放非加密工作区，加密工作区的入口先灰掉并说明原因。
