# myco App 界面设计规范

新增页面、组件、弹窗之前先读这份。它描述的是 App（`web/src/app`，Wails 窗口里的界面）现在的做法；取值以 `web/src/app/app.css` 顶部的变量为准，这里只解释怎么用。

经典的 `myco ui`（`web/src/App.tsx`，Tailwind 主题）不在这份规范里。

## 0. 概念：用户只看到四样东西

把用户当成不懂技术的人。界面上只出现这几个词，每个都是他自己的概念（为什么这样改、用户动线和各处取舍，见 [app-redesign.md](app-redesign.md)）：

| 界面上叫 | 是什么 | 底层是什么（只在 CLI 和成员卡片的「详细信息」里出现） |
| --- | --- | --- |
| **工作区**（Workspace） | 一个团队的地盘，里面有项目和成员；自己一个人用的就是"我的工作区"。工作区之间完全隔开：一次只看一个，切换后所有页面、弹窗、筛选都只在这个工作区里，不出现"全部工作区"，也不让用户再选工作区 | Hub |
| **项目** | 一件要做成的事，和一起做这件事的成员 | project |
| **agent**（成员） | 一个有名字、有头像、有分工的 AI 同事 | 节点（AI 会话） |
| **电脑** | 交给 agent 用的一台电脑上的一个文件夹，agent 在里面跑命令，打开是终端 | shell / exec 节点（以及它所在的 machine） |

- 节点、机器、Hub、runner、allow_from、token 这些词不出现在主流程里。
- **一台电脑上可以有多个工作区**（`myco hub up --name`）。界面上仍然只说「工作区」：切换器里这台电脑上的工作区带一枚「这台电脑」小标签，菜单里有「在这台电脑上新建工作区」（先问工作区名，内部名自动生成：英文名变成小写字母和横线的名字，中文名用 `ws-2`、`ws-3`，按已有的递增；起来后自动加入并切过去）。设置里「这台电脑上的工作区」一行一个，写名字、地址、访问范围（只在本机/局域网、Cloudflare、Tailscale），以及「开放到公网」「停止」（只有一个时和以前一样）。第一次用、还没有任何工作区时，仍然走欢迎页的一键启动。
- **重新接入**：云端 agent 的沙箱是临时的，凭证会丢。成员卡和 AI 同事详情的「身份与绑定」里有一行「重新接入」，只有能管理它的人才看得到。还没有链接时是一句说明加「生成链接」；有了就写「上次重新接入：X 前 · 在 <沙箱>」或「还没用过」，后面跟「生成新链接」「作废」。生成后弹窗给出可复制的命令（`curl -fsSL … | sh`），并说明：把这一行发给那个 agent，或者放进它的项目说明或记忆里，它在新沙箱里跑一次就接回来了；这一行等同于凭证，别公开。生成新链接或作废之前，先说明旧的链接会立刻失效。工作区太旧、没有这条链接时，这一行不显示。
- **模型、推理强度和额度**：「运行」里，runner 方式、CLI 是 Claude Code 或 Codex 的 agent 有三样东西。模型和推理强度各一行，写着现在用的值和它的来源（App 设置 / 它自己报的 / 上一轮观察到的…）；能管理它的人把值换成下拉里的（Claude Code 是 fable、opus、sonnet、haiku，Codex 是当前值和几个常见名，另有「自定义…」），或者选「跟随电脑设置」，改完写一句「下次唤醒时生效」。推理强度 Claude Code 是 低/中/高/很高/最高，Codex 另加「最低」。额度每个窗口一行，例如「5 小时：已用 62% · 3:40 重置」「7 天：已用 58% · 周五重置」；用到 90% 以上是琥珀色，用完是红色并写「额度用完，X 重置」；数据超过一小时就在下面补一句「X 前的数据」。电脑页上这台电脑的 agent 行，额度紧张时也带一个小提示。会话内接收（inbox wait）的 agent 只有一句「模型和额度由它自己的会话管理，myco 拿不到也改不了」，model_source 是 self 时显示它自己报的模型；工作区太旧、没有这个设置接口时不给编辑控件，只读显示。
- **运行权限**：「运行」里的权限显示实际在用的级别（只读 / 工作区 / 完全），App 有覆盖值时带「（App）」。只有 agent 的主人能改；无主 agent 由工作区主人改，管理员没有额外的修改权。选项包括「跟随电脑设置」，上限取电脑报告的上限与实际权限中较高的一档，更高的选项灰掉并说明在那台电脑的 `~/.myco/machine.yaml` 里设置 `spawn.max_access`；本机沿用「在这台电脑上允许」入口。没有报告上限的旧 runner 只读并提示升级。选「完全」先确认没有沙箱、能读写任何文件；保存后下次唤醒生效，不用重启。
- 名字：agent 用它自己起的显示名（加入的那句话会让它用 `--display-name` 写上分工）；没有就用"文件夹 助手"（`myco 助手`），重名的按加入顺序叫"二号""三号"。电脑叫"电脑名 · 文件夹"（`Studio Mac · myco`）。都在 `nodeName()` 里。
- 头像：每个 agent 是一个像素小蘑菇（`persona.tsx` 的 `Avatar`），帽子颜色、斑点、表情由它的 id 决定，永远一样；右下角小角标是 Claude（橙色星号）/ Codex（蓝紫色圆底白色 >_）；左下角小点是状态。电脑的头像跟着它的系统：Mac 是一个苹果（浅色模式石墨灰，深色模式银色），Windows 是四色田字格，Linux（包括 WSL）是一只企鹅（深色模式下身子调亮一点，免得和底色混在一起），不知道系统或在云端时是黑底终端屏幕。人是名字首字的圆形。头像可以自己换（`AvatarPicker.tsx`）：成员资料卡里点大头像（悬停时右下角出现小相机）打开「换个头像」——上面是预览和「用一张照片」「用回原来的」，下面「或者，挑一个蘑菇」：一排 10 种帽子颜色、一格 12 种样子（斑点 × 表情）、「头上长一棵小芽」。照片在 App 里从中间裁成方块、缩到 256px 再发。换好的头像存在工作区上，大家看到的一样；电脑和人只能用照片。工作区版本太旧时说「这个工作区的 myco 版本太旧，还不能换头像」。工作区自己的头像（彩色方块里的首字）在设置里铅笔打开「工作区的名字和头像」：8 种颜色或一张照片，和名字一样只存在这个 App 里。

## 1. 原则

1. **像一个原生工具，不像网页后台。** 鼠标是箭头不是手型；悬停立刻有反馈，没有渐变；按钮有按下态；能右键的地方都能右键。
2. **安静。** 界面是中性灰。颜色只留给有含义的东西：状态、链接、危险操作。一个画面里最多一个实心按钮。
3. **少画线。** 层级靠明暗和间距表达，不靠边框和分隔线。
4. **一个东西只有一种样子。** 同一种状态一种颜色，同一个图形一种含义，同一类按钮一个样式。
5. **先用已有的。** 下面列的类和组件能满足时，不要新写一套。

## 2. 布局

窗口打开时是最大化的（铺满屏幕，不是全屏），和 Codex、Claude 一样；取消最大化后是 1200×800。Mac 上有刘海时，有成员在干活会在刘海处显示「灵动岛」，设置里可以关（「灵动岛」开/关）。

```
窗口（--chrome）
├─ 侧栏默认 232px（可拖宽，见下），直接在窗口底色上，没有边线
│  ├─ 聊天（最上面，总是在：不在任何项目里的 agent，右边几个小头像；有人在干活时一个绿点，在干的都可能是卡住时换成琥珀点）
│  ├─ 项目（只有名字，不加图标或色块；有成员在干活时右边一个绿点，在干的都可能是卡住时换成琥珀点；按住拖动可以排序：被拖的一行浮起来（阴影、略放大）跟着指针走，其他行平滑让位，松手时滑进位置；顺序按工作区记住，新建的在最上面）
│  ├─ 电脑（Mac 的苹果图标比企鹅、窗格画得小一圈，不挤满方块；也能拖动排序；标题点一下进管理页，+ 给当前项目加一台；下面直接列出每台电脑，屏幕小头像 + 名字，点一下打开终端；在跑命令时一个绿点，在跑的都可能是卡住时换成琥珀点；超过 6 台显示"全部 N 台"）
│  ├─ 成员（右边几个小头像叠在一起，代替图标）
│  └─ 底部：工作区切换器（一般只设一次，所以放下面）；设置从它的菜单进（或 ⌘,），侧栏里不单放设置
└─ 内容面板（--bg），四周留 8px，圆角 10px，细描边 --panel-shadow
   ├─ 顶栏 40px（Mac 上 36px，和红绿灯对齐）：侧栏开关 + 页面名称（项目页不写，项目名在下面）
   └─ 页面
```

侧边栏可以拖宽：鼠标移到它右边缘（和右侧面板之间的缝）会出现一条灰线，拖动调整宽度，200–420px，右边页面至少留 520px；宽度记在这个 App 里，双击边缘恢复默认（232px）；往左拖到底松手就收起边栏，再打开还是原来的宽度。键盘聚焦到边缘时左右键也能调。

项目页是三栏里的后两栏（`ProjectSpace.tsx`）：中间是你和协调者的对话（打开一个成员时，中间再分成左右两栏），右边 248px 是成员和电脑，标题旁的按钮可以把它收成 56px 宽、只有头像的一条（悬停看名字和在做什么，记住收起状态）。窄于 900px 时右栏收起，成员变成标题下面一排头像。

- 页面内容用 `.app-page`：最宽 880px，居中，内边距 `18px 20px 40px`。
- 页面第一行是 `.app-page-head`：左边一句概况（`.app-summary`），右边这个页面的"新建"按钮。
- 需要并排两栏（列表 + 详情）时照对话页的 `.conv-split` 做，中间只有一条分隔线。
- 详情用右侧浮层（`.app-inspector`）：宽 420px，四周留 8px，圆角 10px。头部只有一行：图标、名称、状态、关闭。
- 表面一共三层，由深到浅：窗口 `--chrome` → 面板 `--bg` → 卡片 `--card`。不要再加第四层。

## 3. 颜色

所有颜色都用变量，不要写死色值（终端除外，见 6.10）。浅色和深色各有一套值，写在 `.app-shell` 和 `.dark .app-shell` 上。

| 变量 | 用在哪 |
| --- | --- |
| `--chrome` / `--bg` / `--card` | 窗口 / 面板 / 卡片 |
| `--fg` / `--fg-2` / `--muted` / `--faint` | 正文 / 次要文字和图标 / 说明文字 / 占位和禁用 |
| `--pill` / `--pill-hover` | 输入框、灰按钮、行悬停的底色 / 它们的悬停和选中 |
| `--nav-hover` | 没有底色的按钮悬停时的底色 |
| `--line` / `--line-2` | 表面的描边 / 卡片内部的分隔线 |
| `--btn` 系列 | 实心主按钮（浅色下近黑，深色下近白） |
| `--green` `--green-soft` | 工作中、在线、成功 |
| `--accent` | 文字链接 |
| `--amber` `--amber-soft` | 需要注意、部分可用 |
| `--red` `--red-soft` | 失败、连不上、危险操作 |
| `--focus` / `--ring` | 输入框聚焦的细线 / 键盘焦点环 |
| `--pop-shadow` | 浮层（菜单、详情、弹窗）的阴影 |

状态和颜色的对应是固定的，任何页面都一样：

| 状态 | 颜色 | 点的类 |
| --- | --- | --- |
| 工作中 / 处理中 / 在线 | 绿 | `.dot.working` |
| 需要注意 | 橙 | `.dot.pending` |
| 空闲 / 已完成 | 灰（`--muted`） | `.dot.idle` |
| 离线 / 排队中 | 浅灰（`--faint`） | `.dot.offline` |
| 失败 | 红 | `.dot.failed` |

绿色不用来做按钮底色，也不用来装饰。

## 4. 文字

字体是系统字体（SF + 苹方），等宽字用 `ui-monospace`。数字用等宽数字（已全局开启）。

| 字号 | 字重 | 用在哪 |
| --- | --- | --- |
| 11 | 400 / 500 | 分组标题、字段标签、标签、时间 |
| 11.5 | 400 | 行的第二行、提示 |
| 12 | 400 | 页面概况、弹窗说明、区块操作 |
| 12.5 | 400 | 按钮、输入框、键值表 |
| 13 | 400 | 正文（默认） |
| 13 | 500 | 行标题 |
| 13 | 600 | 顶栏的页面名称 |
| 13.5 | 600 | 弹窗标题 |
| 15 | 600 | 详情浮层的名称、空状态标题 |
| 21 | 600 | 文档型页面的大标题（目前只有项目页） |

- 一个页面里不要超过四种字号。强调用字重和颜色，不用再大一号。
- 文档型的页面（项目页）整体比列表页大半档，照 `.app-project` 的写法。
- 等宽字只用于：节点名、ID、路径、命令、版本号、地址。
- "文字大小"设置会把整个页面缩放 1 / 1.08 / 1.16 倍。所以**不要拿鼠标坐标直接当 `left`/`top`**，浮动的东西用 `useContextMenu`，它处理了缩放。

## 5. 尺寸

| | 值 |
| --- | --- |
| 圆角 | 6（图标按钮、侧栏项、菜单项）· 7（按钮、输入框、分段控件）· 8（行悬停、筛选框、页面级按钮）· 9（菜单）· 10（面板、详情浮层、终端）· 12（卡片、弹窗）· 999（状态标签、头像） |
| 控件高度 | 19（状态标签）· 22（小按钮）· 24（区块操作）· 26（按钮、图标按钮、分段控件）· 28（输入框、下拉、搜索、侧栏项、页面级按钮） |
| 间距 | 4 的倍数为主：行内 8，字段之间 12，区块之间 16–18，面板四周 8 |
| 描边 | 表面用 `box-shadow: 0 0 0 0.5px var(--line)`；卡片内部分隔用 `1px solid var(--line-2)` |

分隔线只出现在两种地方：键值表（`.app-kv`）和设置行。列表的行与行之间不画线。

## 6. 组件

### 6.1 按钮

按"这个动作有多重要、在哪"选，不要按喜好选。

| 类 | 样子 | 什么时候用 |
| --- | --- | --- |
| `.app-btn.app-btn-primary` | 实心，近黑或近白 | 弹窗的确认按钮；空页面中间的引导按钮。一个画面最多一个 |
| `.app-btn` | 灰底 | 取消、次要操作、卡片里的普通按钮 |
| `.app-btn.app-btn-quiet` | 平常只有图标和文字，悬停才有淡底和细边 | 页面顶部的"新建"类动作（添加节点、添加机器、发任务、邀请成员） |
| `.app-group-action` | 小号文字按钮，悬停有淡底 | 区块标题右边的操作（编辑、上传、全部对话、刷新） |
| `.app-btn.app-btn-plain` / `.conv-head-icon` | 26px 方框里一个 16px 图标 | 只有图标的按钮，必须带 `title` 和 `aria-label` |
| `.app-btn.app-btn-danger` | 浅红底红字 | 移除、删除，以及危险操作的确认 |
| `.app-summary-action` / `.app-kv-link` | 绿色文字 | 真正的链接：跳到别处、行内的"查看" |

- 每个按钮都要有悬停、按下、禁用、键盘焦点四种状态；用上面的类就自带。
- 按钮不可点时要说明原因：弹窗里用 `.app-modal-hint` 写在按钮左边。
- 一个按钮下有两三个选择时，用一个按钮加下拉菜单（`useContextMenu().openUnder`），不要并排放两个。

### 6.2 输入

- 文本框 `.app-input`，表单里的下拉 `.app-select-field`，工具栏里的搜索 `.app-search` 和筛选 `.app-select`。都是灰底、无边框。
- 聚焦是一条 1px 的中性细线（`--focus`），不要发光。
- 字段用 `label.app-field` 包起来，标签是 `.app-field-label`。必填项不加星号；可选项在标签里写"（可选）"。
- 表单只默认露出必须填的。其余收进 `details.app-advanced`（"更多选项：……"）。
- 二选一、三选一用分段控件 `.seg`。弹窗里的页签用 `.seg.seg-fill` 占满一行，设置里按内容宽度靠右。

### 6.3 列表和行

- 一组行放在一张卡片里：`.app-list` 里放 `.app-row`（节点、机器）或 `.conv-row`（对话）。
- 行的结构：左边图标，中间两行（标题 13/500，说明 11.5 灰），右边状态或数量，最右一个 `›`（`.app-chev`）表示能点进去。
- 悬停是一条圆角色带，选中是更深一档的填充。不用左边的色条。
- 行里的状态用小圆点，不用整行变色。离线的行整体降到 55% 不透明度。
- 分组标题在卡片外面的上方（`.app-group-title`），右边可以放区块操作。

### 6.4 键值表

详情里的"名称—值"用 `.app-kv`：左边灰色标签，右边值靠右。ID、路径、命令加 `.mono`。能点的值后面带 `›`。

### 6.5 弹窗

用 `dialogs.tsx` 里的 `Modal` 和 `ConfirmDialog`，不要自己写遮罩。

- 标题一句话说清要做什么，下面可以有一句说明。
- 按钮在右下：先"取消"，再确认。确认按钮写具体动作（"开始会话""移除"），不写"确定"。
- 弹窗里需要提醒的话（比如「让 agent 在这台电脑上跑命令」）用 `.app-notice`：灰底、盾牌或信息小图标、正常字色，不用红色块（`.app-warn` 不再用于这类提醒）。
- **给项目加电脑**：最上面是「已有的电脑」（工作区里还没进这个项目的电脑），每台一行，「加进来」一键加入，并让项目里的 agent 能给它发命令；下面「或者，用一台电脑上的另一个文件夹」才是新开一个。
- 危险操作用 `ConfirmDialog`，要**平静**：标题是一句短问话（「删除这个 agent？」「让它下线？」），不把长 ID 塞进标题；`subject` 放一行"是谁"（头像 + 显示名，ID 用小号等宽字写在下面）；`description` 用一两句大白话说会发生什么，`consequences` 是一句更浅的补充（比如「和它的聊天记录会留着」）。**不要红色警告块**，红色只留给确认按钮（浅红底红字）。
- 详情里的操作行（`.app-action-row`）每行前面一个图标；有当前值的（比如「允许谁派任务 · 任何 agent」）把值写在箭头前面。危险行（`danger`：下线、删除）平时和别的行一样颜色，鼠标移上去才变红，也不带箭头（点了会先确认）。
- 删除机器和删除节点不同：先用 dry-run 拿到会一起删除的节点，弹窗里按显示名列出来，写明「这台机器上的 N 个节点会一起删除；对话记录保留」；机器还在线时再加一句：那台电脑上的 runner 会被拒绝并停下，要彻底卸载就在那台电脑上运行 `myco runner service uninstall`（命令用 `.app-command` 加复制按钮）。确认按钮写具体数量（「删除机器和 N 个节点」）。入口在机器详情的「操作」里，用 `.app-action-row danger`，只给机器主人、Hub 所有者和管理员看；删完关掉详情并刷新列表。
- 弹窗只在打开时重置字段，不要在每次渲染或轮询时重置。

### 6.6 右键菜单

能点的行都要有右键菜单，用 `ContextMenu.tsx` 的 `useContextMenu`。

- 第一项是左键点击会做的事（"打开""查看详情"）。
- 中间是这个对象的其它操作。
- 分隔线之后放"复制……"。
- 危险项标 `danger`，放最后。
- 不可用的项置灰（`disabled`），不要藏起来。

### 6.7 标签

- 状态用 `.app-pill`（带圆点，全圆角）：`green` / `amber` / `red` 或默认灰。
- 分组和 `#标签` 用 `.app-label`。
- 一行里最多显示三个标签。

### 6.8 空状态

- 整页为空：`.app-empty`，一个图标、一句标题、一句说明、最多一个实心按钮。
- 搜索或筛选没有结果要单独说（"没有匹配的节点"），不要和"还没有节点"用同一句。
- 卡片里为空：一行 `.app-empty-note`。
- 没有选中任何东西的大块空白（对话页右侧）：用很淡的 logo 做底纹，加一句提示。

### 6.9 提示和错误

- 行内错误用 `ErrorText`：先说发生了什么，再说可以怎么办。连不上 Hub、Hub 版本太旧有现成的说法，不要把原始报错直接给用户。
- 警告用 `.app-warn` / `.app-notice`（橙色图标加一句话）。
- 加载用骨架（`Skeleton.tsx`），形状和加载完的内容一致。不要整页转圈。
- 页面数据自己会刷新（每 5 秒），不要放刷新按钮；⌘R / Ctrl+R 可以立即刷新。

### 6.10 终端

和 exec、shell 节点的往来用 `Terminal.tsx`（`.term`）。它在浅色和深色界面下都是深色的，颜色写在 `.term` 自己的变量里。不管是你自己的会话还是旁观别的节点，都是同一个样子：

- 铺满标题栏以下的整个面板，没有卡片、边距和分隔线。
- 字是 12px、行高固定 17px 的等宽字（`ui-monospace`，Mac 上是 SF Mono），不开连字。`.term` 里不用全局的 `antialiased`，保留系统自己的字体平滑，深底上的浅色等宽字才不会发细。
- 每条命令就是"`❯` 命令"一行，下面直接是输出；两条命令之间空 8px。`❯` 是绿色，用 `PromptSign` 画（SVG，一个字符宽），不要打字符，各家等宽字体里它长得不一样。
- 命令是最亮的一层（500 字重），输出明显暗一档，"谁 · 时间"、提示再暗一档。不要整片近白字配近黑底，看久了很累。
- 输出原样显示，stderr 不标红。上一条命令失败，下一个提示符的 `❯` 变红，不用标签和红边。
- 太长的命令折叠起来，末尾是省略号，点命令本身展开、再点收起（悬停时命令行有一层很淡的底色）。不另加"展开"按钮行。
- 一行排到右边缘才折行，可以从单词中间断开，和终端一样。
- 命令在跑的时候，输出后面是一个闪烁的方块光标。

两种场合的差别只有这些：

**你自己的 shell 会话**要用起来像一个终端：

- 提示符前面带蓝色的工作目录；最后一行是输入行，点面板任意位置都聚焦到它，↑↓ 翻历史命令。
- 不显示谁发的、时间、耗时、退出码（悬停在命令行上能看到）。
- 底部状态行在命令执行时变成"正在执行 · Ctrl+C 停止"。
- `clear`（或 Ctrl+L）由 App 自己处理，不发给节点：之前的内容移出屏幕，顶部留一行暗字可以点回来。清屏记在本机（`localStorage`），重启 App 后仍然有效。

**旁观别的节点跑命令**是一份记录，要看清是谁、什么时候跑的：

- "谁 · 时间"用小号界面字体写在一串命令的上方，像聊天分组一样：只有发送者变了或者隔了 10 分钟以上才再写一次，上方多空一点。耗时在命令行的悬停提示里。
- 命令一律只显示一行（自己的会话里是三行）：记录是给人扫的，一列整齐的命令比一大片换行的长命令好读。
- 输出超过 7 行只显示最后 6 行（命令跑得怎么样一般在最后），上面一行暗字"… 前面还有 N 行"，点了显示全部。
- 失败的命令在输出下面用暗红色写一行"退出码 N"。不要把这些信息写在命令行同一行的右边：命令一长就会被挤到单独一行，夹在命令和输出中间，看起来很乱。
- 没有输入行，面板下面是"只能查看"的说明栏。

**别的 agent 发给这台电脑、可能已经卡住的命令**不在终端里（终端只显示你自己的往来），在标题栏下面用一条琥珀色细条说明：

- 一行"这台电脑上有 N 条命令可能卡住（来自 X、Y）"，前面一个琥珀点，后面是「查看」和（有权限时）「全部停止」。
- 「查看」展开逐条：命令内容（没有内容就只写来源）、来源、多久没动静（"1 小时没有动静"），每条一个「停止」。命令只显示一行，太长用省略号，悬停看全文。
- 只有你能管理这台电脑或者它是你的时才显示停止按钮，否则只提示；停不了时把错误写在提示条里。
- 你自己发的命令仍然用对话里那一行「可能卡住」和「停止」「重发」，不在这里重复。

侧栏里电脑、项目和聊天的小点同理：有没卡住的活干着是绿点；在干的活全都可能是卡住时换成琥珀点（`title` 写"可能卡住"），不再显示绿点。

### 6.11 和 agent 的对话

「我的对话」是一个 agent 聊天窗口（`ConversationDetail.tsx`、`TraceView.tsx`），不是聊天软件的左右气泡。

- 一栏，最宽 760px，输入框和它同宽。
- 我说的话是右边的小气泡（`--pill` 底，圆角 16）。agent 的回复不带气泡，正文铺满整栏，按 Markdown 排版。
- agent 做了什么（过程）夹在我的消息和它的回复之间，靠左，像 Claude Code、Codex 那样排：它中途说的话直接显示成正文（Markdown），不折叠；它的思考算过程，和两段话之间的一串步骤（跑命令、读改文件）一起折成一行灰字摘要（"想了一下、跑了 3 条命令、改了 1 个文件"），点了才展开（展开后思考是带脑袋图标的一行，再点看全文）；不再在正文里铺一段淡色文字。运行中，最新那一串的那一行写"现在在做什么"，前面是走路的小蘑菇、后面是用时；**任何时候都不自动展开**。结束后最后一行小字是耗时和 token。步骤只标"还在跑"和"失败"，成功不打勾。
- 进展（`myco message progress`）是 agent 一侧的一行灰字。
- 「在干活」只算节点已经接下（acked）的任务：任务还是 delivered（被 inbox pull 拉走但还没 ack）或 held（先收下、晚点再做）时，就和排队一样——节点不算工作中，列表标「排队中」，对话里写「等待中」和「排队中，轮到它时开始」，不转圈、不写「处理中」；节点的「待处理」数也包含 delivered 的任务。
- 任务被接下后长时间没有动静（runner 唤醒的节点 10 分钟，只在会话里接收的节点 30 分钟，节点离线时立刻算），可能是结果丢了：不显示"处理中"和转圈，改成一行"X 小时没有动静，可能卡住了（结果可能没送回来）"，后面是「停止」和「重发」；对话里每一处卡住的任务都这样，不只看最新那条。列表、节点行和详情里把它单独标成"可能卡住"，不算进"处理中"。对话标题栏右边**不再显示**"已完成 / 在干活 / 会话被占用"这类状态（对话底部的蘑菇和提示已经说明了），只在有可能卡住的任务时显示"可能卡住"，点它跳到那条任务。
- 时间和复制按钮平时不显示，鼠标移到消息上才出现，两边的消息都能复制；失败、已停止、加密标记始终显示。
- 只有在旁观两个节点的往来时才显示名字，并且两边都用气泡。同一方连续发的消息算一组，名字只写在组的第一条上。
- 旁观时进展不单独占行：任务还在做，最新一条进展就是对话末尾"工作中"那一行的文字；有了回复，进展折成回复上方一行"N 条进展"，点开看全部。不要让一行进展孤零零地夹在两边的气泡之间，看不出是谁说的。
- 回复（`reply_to`）如果不是紧跟在它回答的那条消息后面（比如对方连发了几个任务），气泡顶部引用原消息：左边一条竖线，发送者名字加原文第一行，点一下跳过去并让原消息亮一下。紧挨着的问答不加引用。
- 左边有一列刻度（`TurnRail.tsx`），你说的每句话一格：当前所在的那一格更长，悬停看这一轮的问和答，点击跳过去。它有自己的一条窄道，不压在正文上；少于两轮时不显示。旁观两个节点时一格是一个任务，预览里会写是谁发的。终端式的对话没有刻度条。
- 运行中：输入框里没有内容时，发送按钮变成停止。这一轮还没答完时，输入框是在对**这一轮**说话，和 Codex、Claude Code 一样：占位写「补充给 X…（⌘↩ 排到下一条）」（Windows 和 Linux 写 Ctrl+Enter），回车把话**补充**给正在做的任务；⌘/Ctrl+回车把话**排到下一条**。取这段对话里最近一条还没有回复、失败或结束的本人任务作为补充目标，即使最新那条任务已经回复。没有正在做的任务时，两种回车都是发一条新消息。不另外放一行"正在处理"。
- **补充**（`steer`）：接在原来那条任务里，气泡里多一段，头顶小标签「补充」和时间，不是一条新消息、不另起一轮；这条任务仍然只有一处转圈/状态，对方把它当成同一件事接着说。带文件时一起补上（工作区 v0.19.2 起；更早的工作区没地方放，改成发一条新消息）。**一切按时间排**：任务有过程时（你发的任务、成员视图里别人派给它的），补充放进这一轮的过程里，按发出的时间插在它的步骤和进展之间，靠右的一个小气泡（标签「补充」），和 Claude Code、Codex 一样：补充之前它做的在上面，之后它做的、它现在的状态（转圈或「在等」）在下面。没有过程的任务（加密的、可能卡住的）：补充和任务之间没有别的东西时接在任务气泡里，隔了别的消息就画在发出的位置，顶上引用它补充的那条任务（和不紧跟着的回复一样，点引用跳回去）。还在跑的任务下面已经有别的消息时，它正在写的回复文字不在上面长出来，回复到了按时间出现在最下面。
- **在对话里找**（`ChatSearch.tsx`）：⌘F（Windows Ctrl+F）或对话头部右边的放大镜，在对话右上角浮出一条搜索栏：输入就找，从最新的一条开始；Enter 往上一条、⇧Enter 往下一条、Esc 关。找的是屏幕上这段对话里的消息（你的、它的回复、补充），每处都用浅琥珀色标出来，当前这处更深，并跳过去闪一下。右边写「2/5」或红色「没找到」；更早的消息还没加载时多一个「再往前找」。两栏并排时 ⌘F 给最后点过的那一栏。
- **回到底部**：往上翻离底部较远时（超过 400px），对话底部中间浮出一个圆形向下箭头；这期间有新消息到，变成「N 条新消息」的胶囊。点一下平滑滚到底，按钮消失。
- **过程只看进度**（设置 › 外观 ›「对话里的过程」：全部 / 只看进度，存在这台电脑上）：只看进度时，对话里每一轮只显示 agent 自己用 `myco message progress` 报的进度（文字、清单计划、截图）和它问你的点选卡，不显示思考、命令和它边做边写的文字；小蘑菇和「在等」照样显示，回复照常。
- **排队中**：⌘/Ctrl+回车的消息先不发，等这一轮答完自动发出，不打断它。输入框上方一条一行：「排队中：」加消息第一行（只有文件就写「（文件）」），右边「编辑」和「撤回」；可以连着排几条，按先后发。「编辑」把这条撤回、内容放回输入框；「撤回」就不发了。这一轮结束前排着的消息不混进对话，结束后才成为普通的一条新消息。工作区 v0.19.2 起由工作区保管（消息带 `after`），更早的工作区先存在 App 里（`queued.ts`，和草稿一样跟着会话走、重开还在），同样自动发出；两种情况上方的样子一样。
- 旁观两个节点时，只要还有没回复的任务（看 `reply_to`，不看最后一条是什么），对话末尾在干活那一方的一侧显示一行"工作中"（`Working.tsx`）：一个像素小蘑菇（myco 是菌丝）原地踏步、冒孢子，后面是节点名、它在做什么、做了多久，后面还排着任务就写"后面还有 N 个任务"。它在做什么：这个任务最新的进展，其次是节点上报的状态（`status_text`），都没有就显示一个随机的俏皮动词（"琢磨中""长菌丝中""捣鼓中"……），每 3.6 秒换一个。任务还在排队时小蘑菇站着等，文字是"排队中，等它接手"。节点离线、或者任务开着超过 12 小时，不显示。自己的任务不另加这一行（成员视图里别人派给它的任务也一样，它们下面已经有自己的过程）：小蘑菇在运行过程那一行的最前面，代替转圈。排队时它站着等；已接手但还没有步骤和进展时写「已接手，正在启动 Claude Code / Codex」（不知道 CLI 时省略名称），状态用过程每 1.5 秒的轮询更新；开始有动静后、暂时没有步骤时显示俏皮动词；有步骤时显示当前这一步；后面跟已用时间。**一段对话里同时只有一个在动的 loading**：几个任务都还开着时，只有最新那个在做的（已接手或报过进展）显示走路的小蘑菇和当前这一步；更早的还开着的那些不动，没有步骤时是站着的小蘑菇加「还没做完」，有过程的就在过程末尾写一行小字「还没做完」（排队中的照旧显示「排队中」）。末尾别人任务的"工作中"那一行也算在内，谁新谁动。**在做和在等分开**：任务还开着，但 agent 已经不在输出了，就不算在做，不转圈，过程末尾换成一行站着的小蘑菇：它派出去的活还没做完时写「等 X 做完」（X 是派给的人，项目首页里的派活卡片和对话里它发出的任务都算），任务被挂起（`myco message hold`）时写「先放着了，晚点回复」，其它写「在等，还没回复」。怎么算不在输出：它这一轮结束了（`trace follow` 传来的 `turn_end`，或者 runner 那边整轮跑完的 `usage`）；挂起之后没有新的步骤；或者它最后是在说话或思考，之后 2 分钟没有任何动静（命令还在跑不算，跑多久都算在做）。之后又有新步骤，就又算在做。**loading 跟着最下面走**：在做的那个任务下面已经有别的消息（它派出去的活、你的补充）时，转圈的小蘑菇不留在过程末尾（不然会夹在派活卡片上面），放到对话最底下一行（名字、俏皮动词或最新进展、用时）。

### 6.12 项目：和协调者聊，旁边看成员干活

`ProjectSpace.tsx`。用户只跟一个人说话：项目的**协调者**。它拆活、派活；成员之间的往来是记录，不是首页。

- **首页是你和协调者的单聊**（`HomeView`）。上面是项目名、目标，右边两个小图标：全部动态、项目资料（只有图标，悬停写明是什么）；下面直接是对话，**没有对话自己的标题栏**（项目标题已经说明你在哪，再写一遍协调者是重复）。**项目只要有 agent，就一定有协调者**：第一个加入的 agent 自动成为协调者；以前没设的项目，打开时把最早加入的 agent 存成协调者；协调者被移出后，下一个最早的接上。角色是存在项目里的（agent 被唤醒时会看到自己是 `[coordinator]`），不只是界面上叫一叫。在右栏成员上右键「设为协调者」可以换。
- **派活卡片**：协调者每派出一个活，就在这段对话里按时间插一行小胶囊——"派给 [头像] 后端工程师：任务第一行 · 在做/排队中/做完了/没做成 · 时间"。点它在右边打开这个成员，定位到这个任务。只有一行，不展开它们的聊天内容。所有派活都显示，空对话里也显示（按时间排），所以不会一发消息就突然冒出一串卡片；还有更早的消息没加载时，比已加载的第一条更早的卡片等加载了再出现。协调者不是被 runner 唤醒时（比如一直挂着 `myco inbox wait`），它新开的线程不带项目，所以项目的动态里也算上**项目成员之间、不属于任何项目**的线程，不然它刚派的活看不到。
- **点成员：右边再开一栏**（`SplitPanes`）。左边和协调者的对话不关，右边是这个成员的**全部工作**：它收到的每个任务（协调者派的、你派的，按时间排在一起，别人派的在右侧标出是谁）和它的回复（回复别人的标"回复 X"），每个任务下面照样有它的工作过程。在这里发消息，就是直接给它派活；它按顺序排队处理，协调者不会收到通知。电脑在右栏打开的是它的终端。
- 左右两栏的标题栏一样高（`--pane-head-h`，60px，所有对话和项目的标题栏都用它），并排时底边对齐。
- 两栏中间的竖线可以拖（25%–75%，双击回到一半，位置记住）；每一栏标题右边有「只看这一栏」，再点还原；右栏还有关闭。成员列表只在放不下"两栏（各至少 320px）加成员列表"时才收成左栏标题下的一排头像，不然不动，免得打开成员时整页跳一下；两栏都放不下时只显示右栏，关掉回到协调者。右栏打开时淡入一下；加载很快时不闪占位块（超过 0.2 秒才显示）。拖竖线时按指针移动的距离算，不会一按就跳到指针处。
- **全部动态**：原来的群聊卡片流，只读，没有输入框，左上角返回。留着回头查成员之间都干了什么。点卡片同样在右栏打开对应成员。
- **输入框和对话同一栏**：对话内容和下面的输入框共用一组宽度和左右留白（`--conv-col` / `--conv-pad` / `--conv-pad-l`，有左侧轮次导航条时左边多留一点），左右边缘对齐。
- **回复要看得出回的是哪条**：一条回复前面不是它回答的那条消息时（比如一起收了几个任务、最后一起回），回复顶部引用原话（"你 原话第一行"），点一下跳过去；单聊和看两个成员对话都这样。
- **分割线只在隔了很久时出现**：两条消息相隔超过 30 分钟，中间才放一条写着时间的分割线；不再每换一个线程就分一次。
- **一次任务的耗时、token、费用**跟着它的回复走，放在回复下面时间和复制按钮那一行（鼠标移上去才出现），不放在过程下面。
- **对话要稳**：切换会话时，看过的会话第一帧就显示缓存的内容（不先空一下再出来），并在画面绘制前就滚到底部；轮询拿到的内容没变化时不重绘、不滚动，只有新消息才把在底部的对话带到底部，往上翻着看的不动；任务过程、图片晚加载让内容变高时，原本在底部的保持在底部。
- **没发出去的字跟着会话走**（`drafts.ts`）：在一个会话里打了字没发，切到别的会话再回来还在，重开 App 也在；单聊按"工作区 + agent"记，群聊输入框按项目记；发出去就清掉。
- 一次任务的过程里，步骤、它说的话、进展、蘑菇之间留 12px，过程和上面的气泡之间也留 12px；进展时间线里每条上下各 6px，不挤成一团。
- **进展（`myco message progress`）写在任务的工作过程里**（`TraceView`）：按时间插在步骤之间，连续几条是一条小时间线：左边圆点连一根细线，文字比回复浅一档（`--fg-2`，12.5px），右边是时间（24 小时制），还在干活时最新那条的圆点是绿色——和回复一眼分得开，也不再是任务下面一行行灰色小字；还在干活时，蘑菇和“捣鼓中 · 时间”永远在最下面，不会出现在进展上面。没有 runner 的 agent（挂着 `myco inbox wait` 的）没有步骤记录，过程里就只有它报的进展加最下面的蘑菇。进展可以带图片和文件（`myco message progress --attach`）：显示在那条进展文字下面，图片比消息里的小一号（一张最宽 260px），点开看大图，其它文件一行，点了存到「下载」。
- **回复「长出来」**（`Reveal.tsx`）：你正看着对话时新到的回复（以及运行中 agent 新说的话）按块出现——段落、列表项一块块，代码块和表格整块——每块轻轻淡入，按每秒约 450 字的节奏，整条最多约 2 秒；短的（80 字以内、一块）直接出来，JSON 和超过 30 行会折叠的直接出来。显示的永远是原文的开头部分，所以最后一步就是平常的样子，结束时不跳。你一滚动、点一下或按键，剩下的立刻全显示；打开对话、切回来、翻历史时都直接全显示；系统开了「减少动态效果」就不做。runner 的 agent 正在写的那段话（最后一步之后的文字）运行中就显示在过程里，回复到了直接显示，不再长一遍。
- **找任何东西（⌘K，Windows Ctrl+K）**（`CommandPalette.tsx`）：边栏顶上一条「搜索 ⌘K」，或按快捷键，屏幕上方浮出一个框：输入就找所有工作区里的成员、项目、电脑（按名字和介绍），以及你自己的对话里的消息（每个工作区的 Hub 按内容找，停顿 0.25 秒后才问）；结果按「成员 / 项目 / 电脑 / 消息 / 前往」分组，↑↓ 选、回车开、Esc 关。消息一行是对方的名字、找到的那句话前后几个字和时间；打开就是那段对话，跳到那条消息，对话里的搜索栏同时打开、标出这个词。成员和电脑打开它的对话或终端，项目打开项目首页，必要时先切到它的工作区。
- **翻译**（`translate.tsx`，后端 `internal/console/translate.go`）：agent 回复的时间旁有「翻译」，点了这条就换成 App 语言的译文，下面一行小字「已翻译 · 显示原文」；再点「原文」或「显示原文」回到原文。设置 › 翻译：「自动翻译」开了以后，agent 的回复、进展和过程里不折叠的文字（两串步骤之间它说的话；折起来的思考、命令一律不翻），只要跟 App 的语言不一样（按汉字和英文单词的比例判断，代码、路径、链接不算）就自动翻；默认关，因为打开后这些消息会发给翻译服务。翻译服务三选一：DeepL（默认）、Google 翻译、OpenAI 兼容（填地址、模型；OpenAI、DeepSeek、OpenRouter 都行），都要密钥；没填好密钥之前，消息旁没有「翻译」，自动翻译也不生效，设置里那一行提示先选服务、填密钥。密钥存在系统钥匙串里，页面上只显示「已保存在系统钥匙串里（不显示）」，可以删掉；「试一下」翻一句示例。代码块原样不翻。额度用完、密钥不对、连不上时，译文那一行写原因。系统自带的翻译（macOS 的 Translation 框架只能从 Swift 调，macOS 26 之前还要挂在界面上；Windows 没有）暂不支持。
- **头像只能用图片**：「用一张照片」只接受 PNG、JPEG、WebP、GIF。Mac 桌面版用系统自己的选文件面板，只列图片（网页的选文件框在 Mac 上会列出所有文件）；其它地方用选文件框，选了别的会说「只能用图片：PNG、JPEG、WebP 或 GIF」。后端按文件内容判断，改了扩展名的文本也不行。
- **正在写出的正文和思考**：delta 片段按块拼接，在下一次过程轮询前通过 `Reveal` 匀速接续长出来，正文末尾带光标，思考沿用步骤行的默认折叠，写「正在想…」。同类完整正文/思考到来时替换增量，工具步骤到来时清掉前面的增量，避免重复；减少动态效果时直接显示已收到的内容。计划卡片只让新条目淡入，勾选状态做短过渡，不重播整张卡。
- **语音输入**（`Dictate.tsx`）：麦克风在输入框右下角、发送按钮左边（和 Codex、Claude 一样）。语言跟 App 的语言设置走（中文界面听中文，英文界面听英文），不跟系统。Mac 上 App 自己用 Apple 的语音识别听（能在本机就在本机），边说边把字写进输入框、接在已经打的字后面，按钮变红轻轻呼吸，说完自己停，或者再点一下停；第一次会弹「麦克风」和「语音识别」两个系统授权，没授权时按钮变琥珀色、悬停说去哪里打开。Windows 上先把这个窗口的输入语言切到 App 的语言，再打开系统的语音输入（Win+H），由系统打字。浏览器里（`myco ui`）有语音识别接口时网页自己听，和 Mac 一样。听的时候你一打字或者发出去，它就停，不会再往输入框里写。都没有就不显示按钮；终端里没有。停顿不会断：Mac 桌面版的系统语音识别（本机识别）每停顿一下就结束这一段，App 接着开下一段，说过的留着、新说的接在后面；浏览器的语音识别也一样。连着几段都没听到声音才自己停（或者再点一下麦克风）。
- **输入框翻历史**（`inputHistory.ts`）：输入框是空的时候按 ↑ 拿出最近发过的一条，再按往前翻，↓ 往回翻，翻过最新一条回到空框；只从空框开始，所以正在写字时方向键照常移动光标；多行的消息里 ↑ 只在第一行、↓ 只在最后一行生效。单聊里翻的是这段对话里你发过的任务和补充；群里的输入框（「聊天」页、没有协调者的项目）在 App 里记最近 50 条。
- **排队**：⌘↩ 排的几条一条接一条：每条排在前一条后面，前一条做完才发下一条；发出去的消息放在它前面那条的回复后面，而不是写下它的时间。撤回或编辑排着的一条，后面的会重新排到它原来等的那条后面，不会提前发出。
- 群里的输入框（`ProjectSpace` 的 `Composer`）和单聊一样：「Enter 发送 · Shift+Enter 换行」在附件、「发给」后面，输入框有光标时才显示；「只有 X 会收到这条…」放在「发给」的悬停提示里。
- **点选卡（`AskCard.tsx`）**：agent 用 `myco message ask` 问任务的发起人拿主意时，这一轮的过程里出现一张卡片（黑白灰）：小问号、「需要你决定」和时间，问题正文，下面每个选项一行按钮（左边序号方块，标签加粗，说明浅一档），最下面一行「或者直接说…」和发送；还在等时卡片是深一点的边框。这一轮不显示蘑菇和「捣鼓中」，对话标题旁是「等你决定」，输入框提示「回答 X 的问题…」，侧栏那一项和成员栏是琥珀点和「等你决定」（别人的任务写「等 X 决定」）。点一个选项或者在输入框/卡片里打字都算回答（作为补充发出，不再单独显示成补充气泡），卡片变成「问过你」：选中的那项打勾、深边框，其它变灰，底下一行「你选了：…」和时间；agent 在同一个会话里接着干，这一轮重新变成在干活。看别人的任务时卡片只读，写「在等对方决定」。
- **左边的轮次导航条**：你说的每句话是一轮；成员那一栏里，别人（比如协调者）派给它的任务也算一轮，鼠标移上去写明是谁派的。至少两轮才出现。
- **右栏成员的顺序**：协调者永远第一个；然后是正在干活的（最近开始的在上）；再是有活在排队的、空闲的；不在线的在最下面。
- **右栏成员**实时说明每个人在干什么：在干活时是它的状态行或正在做的任务，下面一行小字"谁派的 · 多久了 · 还有几个排队"；排队、不在线、空闲各有说法。协调者名字旁边有"协调者"小标签。
- **空对话**不写"还没有消息"：中间是这个 agent 的大头像，下面一句随机的问话（"想让 X 帮你做点什么？""X 准备好了，交代第一件事吧。"……；协调者那里问项目："你想在「项目」里做成什么？"），再一行小字"一句话就行，它会自己想办法"。两个 agent 之间还没说过话时写"它们还没说过话。"
- **聊天**（侧栏第一项，不在任何项目里的 agent）不用先建项目就能用：加 agent、单聊、群里派活都在这里。它没有协调者，是群聊：卡片流加带收件人的输入框（"发给 [成员 ▾]"，没有"发给所有人"）。输入框上面是整宽的文字区、随内容变高（到 220px 才出现滚动条，靠 JS 量高度，Mac 上的 WebKit 不支持 `field-sizing`；所有输入框都用 `autogrow.ts` 的 `useAutoGrow`：在隐藏的副本上量，不要先把输入框设成 `auto` 再量——那会让上面的对话瞬间变高、滚动位置被截断，打字时整段对话上下跳；输入框变高时，原本在底部的对话保持在底部；只量输入的字，空输入框永远一行高，长的提示文字一行省略；输入框还没有宽度时不量），下面一排工具，左边是回形针（加文件），以后的语音也放这里。
- 在侧栏再点一次当前项目，回到首页（关掉右栏）。
- **计划清单**：一次任务的过程顶上有一张「计划」卡片，像待办清单一样一条条勾掉——做完的打勾、文字划掉变浅，正在做的那条加粗、方框轻轻闪，右上角写「2 / 5 完成」。只用黑白灰：打勾的方框是浅灰底、反白的勾，正在做的方框是深一点的灰边，不用绿色。它来自 Claude Code 的 TodoWrite、Codex 的计划（runner 记进过程，每条带状态 `[x]`/`[~]`/`[ ]`），或者 agent 用 `myco message progress` 发的清单（`- [x] …` 一行一条）；总是显示最新的那一份，清单式的进展不再作为一行文字重复出现；一条进展里清单前后还有话（「好，计划：」）时，清单进计划卡片，那句话照常留在进展时间线里。其它消息里的清单（`- [x]`、`- [~]`、`- [ ]`）也画成同样的方框（打勾浅灰、正在做深灰边、没做浅灰边），不会出现字面的 `[~]`。不做进度条。
- **消息里的附件**（`attachments.tsx`）：图片（png/jpeg/gif/webp/avif/bmp）显示成缩略图，一张时大一点（最宽 320px），多张时方格排列；点一下全屏看大图（暗色遮罩，Esc 或点空白关闭，← → 翻看同一条消息里的图，右上角「保存」）。文字文件（Markdown、日志、代码、JSON、YAML 等，按类型或扩展名判断）是一行，点一下在 App 里打开看（`preview.tsx`）：从右边滑出一块浮层（和成员资料卡一样，浮在页面上，双栏时也不挤占哪一栏），一打开就是满高，文件到了也不会再变大或跳动；头部是文件名和大小，右上角三个小按钮：存到「下载」（存好变成对勾）、全屏（四角箭头，再点一下退回浮层；双击头部也行，这个选择下次打开文件时还记着）、关闭；点浮层外面或按 Esc 关闭。Markdown 渲染成文档（全屏时文字列居中，不会铺满整个窗口），其它按原样等宽显示；超过 2 MB 或不是文字的说「这个文件不是文字，没法在这里看」。HTML 文件打开就是页面（白底，放在隔离的框里：不运行脚本——脚本在预览里直接去掉——不能提交表单、不能打开新窗口，只加载图片、样式和字体），上面「页面 / 源码」可以切换；有上一版时再加「和上一版比」。同一段对话里同名的文件再发来就是新的一版，那一行写「第 2 版」，打开后可以切到「和上一版比」：按行对比，加的浅绿、删的浅红划掉，没变的折成「… N 行没变」。其他文件是一行（图标、名字、大小），点一下存到「下载」文件夹并在访达/资源管理器里显示，存好写「已存到「下载」」。图片读不到时（旧版工作区、文件已过期）退回成一行。只有上面这几种位图会在 App 页面里直接显示，SVG、HTML 等一律当下载处理（不能在 App 里执行）。端到端加密的附件由 App 本地后端先解密。你自己从 App 发出的文件，App 本地留一份（用缓存的钥匙加密，最多 300 MB、14 天），缩略图、看大图、保存都先用这份：不用再从工作区取，旧版工作区上也能看，重开 App 也在。
- **发文件**（`attach.tsx`，单聊和群聊的输入框都有）：点工具栏的回形针选文件，或者直接粘贴（截图、Finder 里复制的文件），或者拖进输入框。文件一加进来就开始上传，在文字上方显示成一样大的小方块（64px）：**图片只显示缩略图**（缩略图已经说明是什么，不写文件名）；其他文件是文件图标，下面是文件名，长了从中间省略、保留开头结尾和扩展名（「2026 年…说明.md」），最多两行。完整文件名、大小和失败原因在悬停提示里。上传中在方块上转圈，失败方块变红（旧版工作区不支持时写"升级它的 myco 就可以"），鼠标移上去右上角出现 × 去掉。文件和文字一起发；只发文件也行，这时消息正文自动写"发来 2 个文件：a.png、b.pdf"。还有文件在上传时发送键是灰的。文件存在工作区上、归你这个发送方，端到端加密的工作区里先加密再上传（和 CLI 一样）。
- 空项目中间只有一件事：小蘑菇、"项目建好了，拉几个 agent 进来吧"、「添加 agent」。
- **项目是可选的**。第一次打开不再要求先建项目，直接进「聊天」：还没有 agent 时，中间是「加一个 agent，直接聊」和一个「添加 agent」主按钮，下面一行浅色小字「要几个 agent 一起做成一件事？建一个项目」。聊天里的 agent 右键菜单最后有「放进项目」，列出这个工作区的项目，点一下就放进去（项目里还没有协调者时它就是协调者，也能用项目的电脑）；资料卡「所在项目」的 + 也能放。

### 6.13 添加 agent、加电脑

`AddToProject.tsx`。

- **添加 agent** 是一个弹窗，四个标签：
  - 「已有的」：这个工作区里还不在这个项目的 agent（在别的项目，或还没进项目），点「加进来」。有这样的 agent 时默认打开这一页。
  - 「这台电脑上的」：这台电脑上最近的 Claude Code / Codex 会话全列出来（多了可以搜，已经加入的排在最后变淡），点「加入」就复制一份会话加入。这台电脑上没有会话时直接打开下一个标签。
  - 「发一句话」：一句很短的话，只有一条命令 `curl -fsSL <链接>/<项目> | bash`，"再照它最后的输出做完"。步骤（`myco join --project … --display-name … --description …`、怎么收消息）都在链接的脚本里，不写进这句话。旧版 Hub 才给完整的步骤。
  - 「新开一个」：选电脑、选用哪个 AI、填文件夹（用过的一点就填）、分工可以不填，点「开一个」。
  - 弹窗开着时，不管从哪个标签加入的 agent 都立刻出现在最下面（"✓ 后端工程师 加入了"），自动放进当前项目，也自动能用项目里的电脑。
- **加电脑**：选哪台电脑（这台电脑排第一，标"这台电脑"；最后一个是"另一台电脑…"）和哪个文件夹（这台电脑上用过的文件夹一点就填）。项目里的 agent 都能用，之后加入的也能。项目里还没有 agent 也能先加电脑（它先锁着，谁都用不了，第一个 agent 加入后就归项目里的 agent 用），所以加 agent 和加电脑没有先后。空项目里两个按钮并排。需要那台电脑同意时用大白话说明（`LocalShellAccess`）。

### 6.14 成员、电脑

- **成员**（`Members.tsx`）像手机通讯录：头像、名字、分工、所在项目的小标签；在干活的排前面；好几天没上线的折叠成"休息中"。点开是右侧资料卡，所有东西都在这一张卡里，不再弹第二个面板：大头像，名字和分工直接点着改（分工只占一行，长了用省略号，悬停看全文），"单聊"，所在项目（点项目名进项目，+ 加到别的项目、悬停"移出"）；下面先回答"它是谁"（用户常常忘了这是哪个会话）：在哪（claude.ai 云端，或"这台电脑 · ~/code/myco"）、用的哪个 AI 和模型、来自哪个会话（在这台电脑上时显示会话的第一句话和上次用的时间）、主人（不是你时）、什么时候加入；再是"最近在做"：最近 7 天做完 / 在做 / 失败三个数，和最近三件事各一行。会话正开着收不到消息时只给一行提示。技能、运行细节、标签、往来、修改记录、身份收在默认折起的「详细信息」里；最后是「管理」（允许谁派任务、复制、踢下线、删除）。卡片可以滚动，里面的东西不会被压扁。
- **电脑**（`Computers.tsx`）是平的一列，一行一台："电脑名 · 文件夹"、所在项目、「打开」，悬停出现"移除"。"连上另一台电脑"在页面右上角，说明只有一句。已经连上的电脑汇成底部一行，点某台可以把它（连同上面的 agent 和电脑）移除：先列出会一起移除的，在线的给出卸载命令，聊过的内容保留。不要把电脑做成"电脑 → 文件夹 → 终端"的层级，用户会以为一台电脑下面还有别的什么。

## 7. 图标

- 窗口框架、侧栏、节点类型、机器类型用 `web/src/components/icons.tsx` 里手画的图标：16px 网格，线宽 1.25，圆头圆角。新增时照这个画，并在样张里和其它图标放一起看。
- 页面内部的操作图标（搜索、加号、编辑、复制等）用 lucide，线宽由样式统一成 1.75，不要单独传 `strokeWidth`。
- 尺寸：顶栏和侧栏 16px，列表行 18px，按钮里 14px，区块操作 14px。
- 一个图形只表示一件事：笔 = 编辑，气泡加号 = 新对话，加号 = 添加，`«` `»` = 收起和展开一栏。
- 不画第三方的官方 logo；各家 CLI 用通用图形区分（Claude 星号、Codex 代码括号、Gemini 四角星、Cursor 指针）。

## 8. 交互

- **鼠标**：控件上一律是普通箭头（`cursor: default`）。只有文字链接是手型。
- **悬停**：背景和颜色立刻变化，不加 `transition`。
- **按下**：按钮有比悬停更深一档的按下态。
- **焦点**：文本框聚焦是细线。用键盘 Tab 到按钮和行上时显示 3px 的焦点环（`:focus-visible` + `--ring`），鼠标点击不显示。
- **动效**：只用于东西出现。浮层和菜单淡入 0.12–0.16 秒，详情浮层从右滑入 0.18 秒。不做循环动画，例外是"工作中"的呼吸点和对话末尾的像素小蘑菇（像素画按整像素跳着动，用 `steps()`）。尊重"减少动态效果"。
- **键盘**：Esc 关闭最上面一层；菜单支持上下键；⌘, 打开设置；新增的全局快捷键写进 `AppMode.tsx` 的同一处。
- **窗口**：顶栏和侧栏头部可以拖动窗口，里面的按钮要标 `--wails-draggable: no-drag`（已有规则覆盖 `button`、`a`、`input`）。

## 9. 文案

- 每句话都用 `L("中文", "English")` 同时给两种语言。
- 按钮和菜单项不以"…"结尾。进行中的状态才用（"正在启动…"）。
- 按钮写动词加对象（"添加 agent""开始对话"），不写"确定""提交"。
- 说明文字说人话，一句说完；不出现接口名、字段名。
- 设置页不用大块红色、绿色：状态写成"● 已连接"这样的字，移除、停止这类按钮平时是描边的中性按钮，指上去才变红；红色实心只留给确认弹窗里的最后一步。
- 用词固定：工作区、项目、agent（成员）、电脑、单聊、任务、补充、排队中。同一个东西不要换说法。不要出现节点、机器、Hub、runner（见第 0 节）。
- 时间用相对时间（"5 分钟前"），需要精确时放在悬停提示里。

## 10. 深色模式

- 两种模式都要做，都要看。颜色全部走变量就自动适配。
- 深色下层级靠"更亮"表达，不靠阴影；浅色下靠阴影和白色。
- 需要半透明叠加时用 `color-mix(in srgb, var(--fg) N%, transparent)`，不要写死黑或白。

## 11. 不要做的事

- 不要用绿色做按钮底色、图标颜色或装饰。
- 不要在列表行之间加分隔线，不要给面板里的内容再套一层带边框的盒子。
- 不要用系统原生外观的控件（下拉、复选框）而不套样式。
- 不要加 `cursor: pointer`（文字链接除外）和悬停的 `transition`。
- 不要放面包屑和刷新按钮。
- 不要在一个画面里放两个实心按钮。
- 不要手改 `internal/web/dist`。

## 12. 做完之后

```bash
cd web && npm run typecheck
cd web && npm run test:ui     # 每个页面在两种宽度、浅色和深色下截图到 web/ui-smoke/（约 2 分钟）
make web                      # 重新生成 internal/web/dist 并提交
make vet && make test
```

`test:ui` 先把 App 构建一次（几秒），再让四种「宽度 × 深浅色」同时跑，每种有自己的 mock 后端和端口（mock 从 7781、App 从 5173 起各占一个），互不影响；跑完列出最慢的几步。改的时候可以只跑相关的步骤，提交前再跑全部：

```bash
npm run test:ui -- --only 单聊              # 只跑名字里有「单聊」的步骤（可写多个）
npm run test:ui -- --combo 1200-light       # 只跑一种（1200-light、1200-dark、760-light、760-dark）
npm run test:ui -- --serial                 # 一种接一种地跑，日志好读
```

提交前自己看一遍截图，至少确认：

- [ ] 浅色和深色都看过。
- [ ] 1200 宽和 760 宽都看过，窄窗口下没有挤坏。
- [ ] 悬停、按下、禁用、键盘焦点四种状态都在。
- [ ] 空状态、加载中、出错、搜索无结果四种情况都有样子。
- [ ] 新的行有右键菜单，新的图标按钮有 `title`。
- [ ] 文案中英文都写了，按钮没有"…"。
- [ ] 没有新写死的色值，没有新的字号。
- [ ] 新页面或新弹窗加进了 `web/scripts/ui-smoke.mjs`，mock 数据（`web/mock/app-server.mjs`）里有对应的内容。

界面在 Mac 上的真实效果（红绿灯对齐、字体、右键菜单位置）要用预览包看，做法见团队文档「开发测试与发版」。
