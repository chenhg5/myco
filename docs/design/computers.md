# 电脑和终端

状态：v0.20.14 起。界面规范在 [app-ui.md](app-ui.md)（第 0 节"概念"、6.13、6.14）。

## 为什么改

以前「电脑」一个词指了三样东西：

- 侧栏和项目里的「电脑」，其实是**一台电脑上的一个文件夹**（shell 节点），打开是终端；
- 「新开一个 → 在哪台电脑上」里的电脑，是**那台电脑本身**（machine）；
- 那台电脑允许什么（能在哪些文件夹开会话、最高权限、能不能开终端）写在它的 `~/.myco/machine.yaml` 里，App 里看不到。

结果最常见的需求走不通。比如"把云服务器（VPS）上的 Claude Code 会话接进来"：

- 得先知道要用「发一句话」（简单模式里还藏着）；
- 工作区默认只在本机和局域网能连，VPS 连不上，弹窗里一个字不提；
- 想在 VPS 上新开一个，要先去「电脑」里加一个文件夹，才能在「新开一个」里看到 VPS；
- 文件夹不在那台电脑允许的范围里，就报错让人去改 yaml。

## 现在的概念

| 叫法 | 是什么 | 底层 |
| --- | --- | --- |
| **电脑** | 一台连进来的真电脑：笔记本、VPS、WSL 各算一台 | machine 和它的 machine 节点 |
| **终端** | 一台电脑上的一个文件夹，agent 在里面跑命令，打开就能看着 | shell / exec 节点 |

agent 跑在电脑上；终端也在电脑上。电脑页一台一张卡，卡里是它上面的 agent 和终端，「详情」里是它允许什么、装了哪些 AI。

## 动线

**把 VPS 上已有的会话接进来**

1. 添加 agent →「连一台电脑」→ 复制命令，在 VPS 的终端里运行（装 myco、连上工作区、起 runner）。
2. 连上后弹窗自动切到这台 VPS，列出它最近的 Claude Code / Codex 会话。
3. 点一个「加入」：在 VPS 上复制一份这个会话加入，原来的会话照常用。

第二次往后跳过第 1 步：添加 agent → 选 VPS → 点会话。

**在 VPS 上新开一个**：添加 agent → 选 VPS →「新开一个」→ 选 AI → 开一个。

- 没装、没登录的 AI 会标出来，选了直接给出在 VPS 上要运行的命令。
- 文件夹可以不填，会建在 VPS 允许的地方。
- 填了范围外的文件夹，开之前就标红，不用等报错。

**连不上时**：给命令之前先看这个工作区的地址，只在本机、局域网或 Tailscale 里能连上时用一句话说清。工作区就在这台电脑上的话，当场就能「开放到公网」。

## 名字和"这台电脑"

- 一个工作区里的电脑不重名：新连上的电脑和别的同名时，Hub 自动在后面加 `-2`、`-3`；改名时和别的电脑同名（不分大小写）会被拒绝（`conflict`）。
- WSL 和它所在的 Windows 主机名一样，所以在 WSL 里连上时默认叫 `<主机名>-wsl`。
- 哪台是"这台电脑"：看这台电脑本地 `machine.yaml` 里记的 machine 节点（`<前缀>machine`）在工作区里属于哪台电脑，而不是看主机名（WSL 和 Windows 同名，工作区还可能把撞名的改成 `-2`）。旧版 App 后端没报这个时，才按加入时的名字、再按主机名猜。

## 电脑怎么告诉 App 它允许什么、有什么

App 经 Hub 给那台电脑的 machine 节点发一个 `cli: "info"` 的请求，用的是开会话那条路（`POST /v1/machines/{id}/spawn`）。machine 节点不开会话，回 `SpawnResult.info`（`api.MachineInfo`）：

- `dirs`：允许开会话的文件夹，原样照 yaml 写（`~/code/x`）；不限制时是 `["~"]`。
- `new_dir`：不填文件夹时新文件夹建在哪：允许时是 `~/myco`，否则是第一个允许的文件夹。
- `max_access`：最高权限。
- `ais`：Claude Code、Codex、Gemini CLI、opencode 各装没装、登没登录、版本，和安装、登录命令。和设置 › 本机 agent 是同一套检查。
- `sessions`：半年内的 Claude Code / Codex 会话，最多 200 个（读最新的 4000 个记录文件；读到需要的几行就停，很快）；已经加入这个工作区的写着是哪个 agent，程序开的（`claude -p`、Agent SDK、`codex exec`、myco 自己）标 `auto`，最多 100 个，App 折起来放在最后。和「这台电脑」的列表是同一套读法。以前程序开的直接不列、只看 30 天、只读 400 个文件，一台常被 myco 用的电脑上几乎什么都列不出来。
- `home`：`~` 在那台电脑上是哪里，App 用它判断一个路径在不在允许的范围里（那台电脑开会话时还会再查一遍）。

电脑记着上一次读到的结果，问它时立刻拿这份回答，同时在后台重新读（超过 20 秒的才重读）；runner 一启动就先读一遍，有会话加入或新开后丢掉重读。问一次要经过工作区转一圈（App → Hub → 那台电脑的 runner → Hub → App），实测 1.7～2.3 秒，压不下去多少，所以 App 自己也记着每台电脑上一次的回答（`machineInfoCache.ts`）：App 一启动、电脑上线时就先问（每台每分钟最多一次），添加 agent 和电脑页的详情先显示上一次的，再在后面换成新的。会话一行接一行淡入。

接入远程会话就是开会话请求带 `fork_from: <会话 id>`、`dir: <会话的文件夹>`，machine 节点早就支持。

**版本**

- 回答 `info` 要那台电脑上的 myco 是 v0.20.14 或之后。更旧的会把 `info` 当成不认识的 AI 拒掉；App 看版本就知道，不去问，直接说「在那台电脑上运行 myco upgrade」。
- Hub 不用升级。老 Hub 会把回答重新编码、丢掉不认识的 `info` 字段，所以 machine 节点在 `reply` 里放一份同样的 JSON 文字，App 后端两处都认。老 Hub 会把这次询问记成一条 `machine.spawn` 审计，新 Hub 不记。
- 不填文件夹时新建：新文件夹可以建在 `~/myco` 下，也可以直接建在某个允许的文件夹下；不在允许范围里的一律不建（以前会先建好再报错，留下空文件夹）。App 还不知道那台电脑允许哪些文件夹时请求的是 `~/myco/<名字>`；`~/myco` 不在允许范围里的电脑会把同名文件夹建到第一个允许的文件夹里，而不是报"不存在"。App 那边也会等问到允许的文件夹再让「开一个」能点。

## 从 SSH 或 WSL 加电脑

现在连一台电脑要：复制命令 → 自己登录那台电脑 → 粘贴运行。能 SSH 上去的电脑、这台 Windows 里的 WSL，App 可以替你做完。思路参考了 Kettu（AGPL，只借思路），但我们的电脑自己连 Hub，不需要它那套 SSH 隧道。

**入口**：「连一台电脑」里多两种方式，排在「复制命令」前面（App 后端：`GET /app/local/ssh-hosts`、`GET /app/local/wsl`、`POST /app/hubs/{id}/machines/connect`、`GET /app/connect/{job}`，`remote.go`、`remote_connect.go`）：

- **从 SSH 配置里选**：列出 `~/.ssh/config` 里的主机（跟着 `Include` 读），每个用系统的 `ssh -G <名字>` 算出真正的用户、地址、端口和跳板，显示成「名字 · user@host:port · 经 跳板」。只拿 Git 用的主机（github.com、gitlab.com、gitee.com 等）不列。也可以手填 `user@host`、端口。
- **这台 Windows 里的 WSL**（只在 Windows 上）：`wsl.exe -l -v` 列出发行版；已经连在这个工作区的标出来。

可以勾几台一起加。每台一行，按步骤打勾：

1. **登录**：`ssh -T -o BatchMode=yes -o ConnectTimeout=15 <名字> 'sh -s'`（WSL 用 `wsl.exe -d <发行版> -- sh -s`），从标准输入送一小段探测脚本：系统、架构、有没有 bash 和 curl、有没有装 myco、什么版本、是不是已经连在这个工作区。
2. **安装并连上**：App 现生成一次性的加入链接（和「复制命令」那条一样，1 次、24 小时），从标准输入送过去执行 `curl -fsSL <链接> | bash`：装好或升级 myco、`machine join`、装后台服务（Linux 上会顺手开 linger）。链接只走 ssh 的标准输入，不出现在任何一台电脑的命令行参数和进程列表里。
3. **等它出现**：等 Hub 上出现这台电脑（最多 60 秒），然后像现在一样切到它，列出它的会话。

**为什么不用配对码**：能用你的 SSH 登录上去，就说明那台电脑是你的，这一步本身就是授权。App 不读、不存任何密钥，用的是你的 ssh 和 ssh-agent；`BatchMode` 让它在要输密码、口令时直接失败，不会卡住。

**出错时**：按 ssh 的报错归类，每类一句话加一条能复制的命令：

| 类别 | 说法 |
| --- | --- |
| 要密码或口令 | App 不能替你输密码或密钥口令。先 `ssh-add` 把密钥放进 ssh-agent，确认 `ssh <名字>` 不用输密码就能登录 |
| 没见过的主机 | 第一次连这台：先在终端里运行 `ssh <名字>`，核对指纹并接受 |
| 主机指纹变了 | 这台主机的指纹和上次不一样，可能换了系统，也可能被冒充：确认后再从 `~/.ssh/known_hosts` 里删掉旧的 |
| 连不上 / 拒绝 / 超时 | 地址或端口不对，或者那台电脑没开、防火墙挡了 |
| 没有 bash 或 curl | 那台电脑上先装 curl（或者 bash） |
| 不支持的系统 | 只支持 Linux 和 macOS；Windows 用「复制命令」里的 PowerShell 那条 |
| 安装或连接失败 | 折叠框里放它最后打印的 30 行 |

**记住怎么连回去**：加成功后，App 在本机记下「这台电脑 ← SSH 名字 / WSL 发行版」（`~/.myco/app-reach.json`，只记名字，不记地址和密钥）。之后：

- **检查**：电脑页「检查和修复」一块，通过同一条路跑一段只读脚本，逐项给结论（最坏的排最前）：myco 版本和位置；后台服务在不在跑、从什么时候起；linger（Linux）；服务配置里的代理；它所在的每个工作区经那个代理、和直连各连不连得上（问 `/v1/health`）；runner 日志最后 20 行。比如「经代理连不上工作区，直连是通的」，说清代理地址和怎么办。代理密码、令牌在离开那台电脑前就遮掉。
- **重启后台**（`myco runner service restart`）、**升级 myco**（同一个安装脚本，用不了 sudo 时装到 `~/.local/bin`，再让服务用新的那个）：做完再自动检查一次；失败时展开它打印的最后几行。
- 不是从 App 加的电脑：这一块先问「它是哪一个」，从 SSH 配置里的主机和这台 Windows 上的 WSL 里选（按名字、主机名先猜一个），记下来，之后一样能检查。
- App 后端：`GET/PUT /app/hubs/{id}/machines/{mid}/reach`、`POST …/diagnose`、`POST …/fix {action: restart|upgrade}`（`remote_diag.go`）。

**范围**：先做 SSH 到 Linux、macOS，和 Windows 上的 WSL。SSH 到 Windows 本身（PowerShell）先不做。App 后端只用系统自带的 `ssh`、`wsl.exe`，不引新依赖。Hub 和那台电脑的 myco 都不用升级。

## 用 SSH 在服务器上装工作区

「加入工作区 › 还没有链接？」里先是「用 SSH 装到服务器上」（和连电脑同一个列表，一次选一台），再是「复制命令」。App 依次：

1. **登录，看看那台服务器**：系统（要 Linux 和 systemd）、是不是 root 或有不要密码的 sudo、有没有 curl、是不是已经装过工作区（`/etc/myco/hub.env`）。
2. **装好工作区**：没装过就运行 `install-hub.sh --domain auto --yes`（自动 HTTPS，地址 `<IP>.sslip.io`，要能开 80、443）；装过就跳过，不改它原来的设置。然后在服务器上 `myco console link` 生成一个 App 链接，只从 SSH 的输出里拿，不显示、不记日志（安装输出里的链接也遮掉）。
3. **加进这个 App**：用这个链接加进来，弹窗关掉，切到新的工作区。

不是 root、sudo 又要密码时不硬来：说清楚，给一条带 `ssh -t` 的命令在终端里跑（会问 sudo 密码）。装好了但这台电脑连不上新地址时（多半是防火墙、安全组没放开 80、443），说清楚，放开后点「重试」会直接加进来，不会重装。App 后端：`POST /app/local/hub-over-ssh`，进度同样用 `GET /app/connect/{job}`（`remote_hub.go`）。

## 还没做

- 允许的文件夹（v0.21.1 已做）：电脑页「它允许什么」里加减文件夹，新建 agent 时文件夹不在范围里旁边有「允许在 … 开工」。规则不变：这是那台电脑自己的，工作区（Hub）改不了；App 只在它自己够得着那台电脑时改：这台电脑直接改 `machine.yaml`，用 SSH / WSL 连上的电脑在那边跑 `myco machine dirs --add …`；别的电脑给出这条命令。去掉最后一个文件夹会被拒绝（一个都不写等于整个家目录）。最高权限（`spawn.max_access`）仍然只在那台电脑上改（这台电脑上有「允许」开关）。
- 手机（iOS）还是"加一台电脑 = 加一个终端"的旧说法。
- 侧栏只列终端，不列电脑；电脑在电脑页。
