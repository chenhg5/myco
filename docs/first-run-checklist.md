# 新用户完整流程：可能卡住的地方和实机测试清单

给在一台**真正空白的机器**上从头试 myco 的人用（像 Mac mini 那位用户的情况）。按顺序做，每一步记下：用了多久、看到了什么、有没有卡住、卡住时「详细信息」里的原文（点「复制」）。

一台机器只试一条路。建议至少试三台（或三次干净的环境）：

| 场景 | 机器 | 路线 |
|---|---|---|
| A | 空白 Mac（没装过 myco、Claude Code 用 npm 装） | App →「在这台电脑上开始」→ 加本机 Claude Code 会话 → 对话 |
| B | 空白 Windows + WSL | App → 加 WSL 里的 Codex / Claude Code（一条命令）→ 加 WSL 终端 → 对话 |
| C | 任意一台，已装 Claude Code 或 Codex | 只用「让 agent 帮我装」那句话，人不手动做任何安装步骤 |

「空白」的意思：没有 `~/.myco`、没装过 myco App、没有旧的 runner 服务。测试前先确认：`ls ~/.myco`（应该不存在），`which myco`（应该找不到）。

---

## 1. 拿到 App

| 可能卡住 | 现象 | 现在的处理 | 测试时看什么 |
|---|---|---|---|
| GitHub 下载慢或打不开（国内常见） | 下载很久或失败 | 没有镜像 | 记下下载用时；不行就试 jsDelivr 或代理 |
| Mac 第一次打开被拦 | 「无法验证开发者」 | DMG 已签名、已公证，正常不会拦 | 双击能否直接打开 |
| Windows SmartScreen | 「Windows 已保护你的电脑」 | Windows 版还没签名，要点「更多信息 → 仍要运行」 | 用户能不能自己找到这个按钮 |
| 下载到的是旧版本 | 版本号不对 | README 链接总是指向最新版 | 设置 › 关于 里的版本号 |

## 2. 第一次打开（欢迎页）

| 可能卡住 | 现象 | 测试时看什么 |
|---|---|---|
| 三个选项不知道选哪个 | 犹豫、问人 | 看用户第一眼选了哪个、为什么 |
| 「让 agent 帮我装」那句话复制后不知道发给谁 | 没有 Claude Code / Codex 的用户 | 没有 agent 的人会不会被这张卡误导 |

## 3. 开 Hub

**本机一键启动（场景 A、B）**

| 可能卡住 | 现象 | 现在的处理 | 测试时看什么 |
|---|---|---|---|
| myco 命令行没装 | 启动失败 | App 自带一份，自动装到 `~/.local/bin` | 启动后 `myco version` 能否找到 |
| 7777 端口被占 | 启动失败 | 自动换端口？（待确认） | 故意先占用 7777 试一次 |
| macOS「是否允许传入连接」弹窗 | 用户点了拒绝 → 别的电脑连不上 | 文档里有说明 | 弹窗出现时机；点拒绝后有没有提示 |
| 代理软件（Clash TUN、公司 VPN） | 「暂时连不上，或者响应太慢」 | v0.19.24 起本机和局域网地址直连 | 开着代理再试一次；看「详细信息」原文 |
| 局域网地址选错（多网卡、VPN 网卡） | 别的电脑连不上 | `MYCO_LAN_ADDR` 可指定；链接是 127.0.0.1 时会警告 | 生成的链接里是哪个 IP |
| Mac 睡眠 | Hub 跟着睡，所有 agent 离线 | 文档里提醒关自动睡眠 | 合上盖子 / 睡眠后再唤醒，多久恢复 |

**服务器（install-hub.sh）**

| 可能卡住 | 现象 | 现在的处理 |
|---|---|---|
| 443 被 nginx / 宝塔占着 | 装不上 | 不带参数运行会检测并推荐 `--behind` |
| 云厂商安全组没开端口 | 自检说「公网不通」 | 自检会指出是安全组 |
| 证书没签下来 | HTTPS 不通 | 自检会指出证书那一层 |
| 服务器下载 GitHub 失败 | 安装中断 | 有 API 兜底，但仍依赖 GitHub |

**加入已有的工作区**

| 可能卡住 | 现象 |
|---|---|
| App 链接过期（24 小时、只能用一次） | 粘贴后报错 |
| 粘贴了入网链接（/j/）而不是 App 链接（/c/） | 报错，用户分不清两种链接 |

## 4. App 连上工作区

| 可能卡住 | 测试时看什么 |
|---|---|
| 左下角一直不是「已连上」 | 多久变成「已连上」；不变时「详细信息」原文 |
| 凭据失效 | 重启 App 后还在不在 |

## 5. 加 agent：这台电脑上的会话（场景 A）

| 可能卡住 | 现象 | 现在的处理 | 测试时看什么 |
|---|---|---|---|
| 列表里找不到自己的会话 | 少了、重复 | v0.20.2 起去重、读 `~/.config/claude` | 列表和 `ls ~/.claude/projects` 对比 |
| 找不到 claude（npm / nvm 装的） | 「复制会话失败」 | v0.20.5 起读终端的 PATH | 用 nvm 装的 claude 试一次 |
| claude 没登录、订阅过期、额度用完 | 复制失败或 agent 不回 | 只显示原始错误 | 「详细信息」写的是不是人看得懂的话 |
| 会话正开在终端里 | 「会话被占用」 | 提示「复制一份来对话」 | 用户能不能看懂 |
| runner 服务没跑或 PATH 不对 | 加进来了但发消息不回 | App 会装 runner 服务 | `myco runner service status`；发一条消息看多久回 |

## 6. 加 agent：别处的（场景 B、C）

| 可能卡住 | 现象 | 现在的处理 |
|---|---|---|
| Hub 只在局域网，云端 agent（claude.ai）连不上 | 句子发过去，agent 报连不上 | 要开隧道；界面上有没有提醒？（待确认） |
| claude.ai 云端环境的网络白名单没放行 Hub 地址 | 连接被拒 | 文档有写，界面没有 |
| Windows PowerShell 执行策略 | 一条命令跑不起来 | 给了 PowerShell 版命令 |
| WSL 没开着 / 被自动关掉 | 加好后一会儿就离线 | 只显示「离线」，不说原因 |
| 同一个会话加进两个工作区 | 消息只收到一边 | v0.20.3 起默认复制一份并提示 |

## 7. 加电脑 / 终端（场景 B）

| 可能卡住 | 现象 |
|---|---|
| 在错误的文件夹里运行了命令 | 终端开在 home 目录 |
| 没允许开终端（shell access） | 「还没允许」，要回那台电脑上改 |
| 电脑睡眠、WSL 被关 | 离线，看不出原因 |

## 8. 第一次对话

| 可能卡住 | 现象 | 测试时看什么 |
|---|---|---|
| 消息发出去没人理 | 一直排队 | 多久开始干活；排队时界面说了什么 |
| 「没送到」 | 失败提示 | 点「重新发送」能不能好 |
| 回复很慢 | 每条都要等几秒到十几秒 | 记下：发出 → 开始 → 第一句话 各用多久 |
| 模型或额度用完 | 失败 | 提示是不是看得懂 |

## 9. 之后的日常

| 可能卡住 | 现象 | 现在的处理 |
|---|---|---|
| `myco upgrade` 报 403 | 找不到最新版 | v0.20.8 起改从 Release 页面读 |
| Hub 比 App 旧 | 某些功能不显示 | 提示 `sudo myco upgrade` |
| 局域网 IP 变了 | 别的电脑全部连不上 | 要重新加入 |
| 快速隧道地址变了 | 全部连不上 | 文档说只适合试用 |

## 测完要交回来的东西

1. 每个场景：每一步的用时，卡住的地方（截图 +「详细信息」原文）。
2. 用户第一次犹豫或者问「这是什么意思」的地方（文案问题）。
3. 场景 C：那个 agent 最后的汇报，以及它中途问了用户哪些问题。
4. 机器信息：系统版本、有没有代理 / VPN、Claude Code 和 Codex 是怎么装的（npm、nvm、官方安装器、Homebrew）。

表里标「待确认」的几项，是我们自己也没确认过的行为，测试时顺便看一下。
